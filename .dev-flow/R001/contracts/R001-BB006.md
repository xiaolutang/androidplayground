## 任务边界

### 做什么（IN scope）

1. **新建 `agent/assessment/confidence_evaluator.py`**（当前为空文件，待实现）：修复置信度评估器，输入 bug_report + trajectory 状态 + kb_context，输出 `ConfidenceScore`（三维分数 + Tier 分级 + reasoning），纯计算函数不持久化（持久化由调用方负责）。

2. **三维打分**（各 [0.0, 1.0]）：
   - `dim_info_completeness`（信息完备度维度）：从 BugReport 字段推断信息完备程度（有无复现步骤 / 堆栈 / 版本 / 预期行为等），映射到 [0,1]。可复用 BB001 ISMResult（若已由上游传入）作为输入信号；若 ISMResult 不可得则基于 BugReport 字段自算。
   - `dim_verification_feasibility`（验证可行性维度）：从 trajectory 状态（Hypothesis 是否 confirmed / 是否有 falsifying_signal / 是否有 expected_signal 命中证据）推断修复方案的可验证程度，映射到 [0,1]。
   - `dim_patternability`（模式化程度维度）：从 KB `pattern` 层检索结果（`kb_context.entries` 中 `layer="pattern"` 的条目数 / top1 similarity / 是否 degraded）推断此 bug 是否已有可复用的修复模式，映射到 [0,1]。

3. **Tier 分级**（三维组合 → Tier 1-4，确定性阈值规则）：
   - **Tier 1（自动修复，提普通 PR）**：三维均 >= `TIER1_DIM_THRESHOLD=0.7`（高置信，design 5.1 第 760 行分流到 BB007 自动修复 `is_draft=false`）。
   - **Tier 2（中置信，提 draft PR）**：不满足 Tier 1，但三维平均 >= `TIER2_AVG_THRESHOLD=0.5` 且无维度 < `TIER2_DIM_FLOOR=0.3`（design 5.1 第 761 行分流到 BB007 draft + rationale）。
   - **Tier 3（仅诊断建议）**：不满足 Tier 2，但三维平均 >= `TIER3_AVG_THRESHOLD=0.3`（design 5.1 第 762 行分流到缺口诊断 GD，但仍可输出诊断建议）。
   - **Tier 4（仅记录）**：其他（三维平均 < 0.3，极低置信，design 第 762 行 Tier3/4 分流兜底）。

4. **KB 模式命中加成**（dim_patternability 计算，design 5.3 第 821 行）：
   - `kb_context` 非 None 且 `degraded=False`，pattern 层有命中（entries 中存在 `layer="pattern"`）→ dim_patternability 基线 = top1 similarity（clamped [0,1]），命中数 >= 2 时额外 + `KB_PATTERN_BONUS=0.1`（cap 1.0）。
   - `kb_context` 为 None 或 `degraded=True`（冷启动 / 低相似度，design 第 821-822 行）→ dim_patternability = `KB_DEGRADED_PATTERN_SCORE=0.2`（明确给低分，design 5.3 指令）。
   - `kb_context` 有 entries 但无 pattern 层命中（其他层命中）→ dim_patternability = `KB_NO_PATTERN_HIT_SCORE=0.4`（有 KB 但无 pattern 模式，中等偏低）。
   - KB 模式命中情况记录到 `ConfidenceScore.kb_pattern_hit`（json：`{"layer": "pattern", "top1_similarity": float, "hit_count": int, "degraded": bool}`）。

5. **ConfidenceScore 产出**（不持久化）：
   - 产出 `ConfidenceScore` 对象（内存中，由调用方 Orchestrator 负责持久化到 `BugReport.confidence_score_id`）。
   - 字段：`tier: int`（1-4）/ `dim_info_completeness: float` / `dim_verification_feasibility: float` / `dim_patternability: float` / `kb_pattern_hit: dict | None` / `score: float`（三维平均，校准用）/ `rationale: str`（分级理由摘要）。
   - `bug_report_id` 留空（由持久化方填充），评估器不碰 DB。

6. **纯计算函数**（不调 LLM）：
   - 三维打分基于规则（BugReport 字段检查 + trajectory 状态检查 + KB 检索结果统计），不调用 LLMGateway。确定性，无随机性。
   - 阈值常量定义在模块顶部（或 config，MVP 用常量），便于校准。

7. **单元测试**：`tests/unit/assessment/test_confidence_evaluator.py`，纯规则测试（确定性，无需 LLM mock、无需 DB），覆盖三维打分 / Tier 分级 / KB 模式命中 / 阈值边界。

### 不做什么（OUT of scope）

- **不实现 Tier 驱动的修复策略**（BB007 负责）：评估器只输出 Tier 分级，不决定走 Tier1 自动修复 / Tier2 draft / Tier3/4 缺口诊断。Orchestrator（ORB01）消费 Tier 决定后续分支。
- **不实现缺口诊断**（BB010 负责）：Tier3/4 的实际缺口识别（gap_type 分类 / CapabilityGap 写入）由 BB010 负责。
- **不持久化 ConfidenceScore**：评估器是纯计算函数，返回内存中的 `ConfidenceScore` 对象。DB 写入由 Orchestrator 负责（关联 `BugReport.confidence_score_id`）。
- **不实现 KB 检索**（BF005 负责）：评估器消费 `RetrievalResult`，不自行调 `KBRetriever.retrieve`。调用方（Orchestrator）先检索再传入。
- **不实现信息完备度评估**（BB001 负责）：dim_info_completeness 可复用 BB001 的 `ISMResult`（若调用方传入），或基于 BugReport 字段自算简化版（不调 LLM）。本任务不实现 BB001 的 LLM 评估逻辑。
- **不调 LLM**：评估器为纯规则计算，不依赖 LLMGateway。信息完备度维度的精细 LLM 判断由 BB001 负责（上游），本任务只在 BB001 结果可得时引用，否则用规则简化版。
- **不做异步接口**：评估器为同步函数（纯计算，无 IO），`evaluate(...)` 为普通 `def`。

## 验收标准（可测试）

### AC-1：评估接口

- **断言**：`ConfidenceEvaluator().evaluate(bug_report, trajectory=traj, kb_context=kb_result)` 返回 `ConfidenceScore` 实例。
- **断言**：`ConfidenceScore` 字段完整：`tier: int`（1-4）/ `dim_info_completeness: float`（[0,1]）/ `dim_verification_feasibility: float`（[0,1]）/ `dim_patternability: float`（[0,1]）/ `kb_pattern_hit: dict | None` / `score: float`（[0,1]，三维平均）/ `rationale: str`。
- **断言**：`bug_report` 参数接受 `BugReport` ORM 对象或 dict（duck typing：访问 `raw_report` / `version_code` / `symptom_type` / `stacktrace` 等属性）。
- **断言**：`trajectory` 参数接受 `Trajectory` ORM 对象或 dict 或 None（None 时 dim_verification_feasibility 给低分 0.3，表示无验证证据）。
- **断言**：`kb_context` 参数接受 `RetrievalResult` 或 None（None 时 dim_patternability = `KB_DEGRADED_PATTERN_SCORE=0.2`，kb_pattern_hit = None）。

### AC-2：三维打分范围

- **断言**：`dim_info_completeness` 始终在 [0.0, 1.0]（clamped）。
- **断言**：`dim_verification_feasibility` 始终在 [0.0, 1.0]（clamped）。
- **断言**：`dim_patternability` 始终在 [0.0, 1.0]（clamped）。
- **断言**：`score` = 三维平均值（`round((d1+d2+d3)/3, 4)`），在 [0.0, 1.0]。

### AC-3：Tier 分级规则

- **断言**：三维均 >= 0.7 → `tier=1`（如 0.8/0.75/0.9 → tier=1）。
- **断言**：三维不满足 Tier1（至少一维 < 0.7），但平均 >= 0.5 且无维度 < 0.3 → `tier=2`（如 0.6/0.5/0.4 → 平均 0.5，无 < 0.3，tier=2）。
- **断言**：不满足 Tier2，但三维平均 >= 0.3 → `tier=3`（如 0.4/0.3/0.2 → 平均 0.3，有维度 < 0.3，不满足 Tier2，但平均 >= 0.3，tier=3）。
- **断言**：三维平均 < 0.3 → `tier=4`（如 0.1/0.1/0.1 → 平均 0.1，tier=4）。
- **断言**：边界稳定性：三维 (0.7/0.7/0.7) → tier=1（均 >= 0.7）；三维 (0.69/0.7/0.7) → 不满足 tier1，转 tier2 判定（平均 0.697 >= 0.5，无 < 0.3，tier=2）。

### AC-4：KB 模式命中加成（dim_patternability）

- **断言**：`kb_context` 提供 pattern 层命中（entries 含 `layer="pattern"`，top1 similarity=0.85，1 条命中）→ `dim_patternability=0.85`（top1 similarity），`kb_pattern_hit={"layer":"pattern","top1_similarity":0.85,"hit_count":1,"degraded":False}`。
- **断言**：`kb_context` 提供 pattern 层命中 >= 2 条 → `dim_patternability` = min(top1 + 0.1, 1.0)（加成 cap 1.0）。
- **断言**：`kb_context.degraded=True`（冷启动）→ `dim_patternability=0.2`（`KB_DEGRADED_PATTERN_SCORE`），`kb_pattern_hit` 的 `degraded=True`。
- **断言**：`kb_context=None` → `dim_patternability=0.2`，`kb_pattern_hit=None`。
- **断言**：`kb_context` 有 entries 但无 pattern 层命中（如只有 negative_knowledge 层）→ `dim_patternability=0.4`（`KB_NO_PATTERN_HIT_SCORE`）。

### AC-5：ConfidenceScore 字段完整

- **断言**：`ConfidenceScore` 对象包含所有字段：`id`（UUID 生成）/ `bug_report_id`（None，由持久化方填）/ `dim_info_completeness` / `dim_verification_feasibility` / `dim_patternability` / `kb_pattern_hit` / `tier` / `score` / `rationale`。

### AC-6：纯计算函数（不调 LLM）

## Tier 分级方案（协商确定）

design 5.1 第 759-762 行明确了 Tier 分流**目标**（Tier1→普通 PR / Tier2→draft PR / Tier3/4→缺口诊断），但未给出具体的三维→Tier 阈值数字。本 Contract 协商确定如下阈值：

| Tier | 条件 | 分流目标（design 5.1） | 语义 |
|------|------|----------------------|------|
| Tier 1 | 三维均 >= 0.7 | BB007 自动修复 + 普通 PR（`is_draft=false`） | 高置信，信息完备+可验证+有模式 |
| Tier 2 | 平均 >= 0.5 且无维度 < 0.3 | BB007 draft + rationale | 中置信，部分维度不足但整体可修复 |
| Tier 3 | 平均 >= 0.3 | BB010 缺口诊断 | 低置信，仅诊断建议 |
| Tier 4 | 平均 < 0.3 | BB010 缺口诊断 | 极低置信，仅记录 |

**阈值依据**：
- 0.7（Tier1 维度门槛）：与 BB001 ISM `SUFFICIENT=0.8` 对齐略低（置信度允许略低于信息完备度，因为 trajectory 和 KB 可补偿）。
- 0.5（Tier2 平均门槛）：与 BB001 ISM `BORDERLINE=0.5` 对齐（临界值，可走 draft 路径）。
- 0.3（Tier2 维度下限 / Tier3 平均门槛）：防止某一维度极低（如 pattern=0.05）但被高平均拉到 Tier2 的情况（短板效应）。
- 阈值参数化，待校准（design 第 826 行明确"阈值参数化待校准"）。

## 实现要点

### Q1：ConfidenceEvaluator 接口？

```python
class ConfidenceEvaluator:
    """修复置信度评估器（纯规则计算，不调 LLM）。

    三维打分（info/verify/pattern）→ Tier 1-4 分级。
    """

    def evaluate(
        self,
        bug_report: BugReport | dict,
        *,
        trajectory: Trajectory | dict | None = None,
        kb_context: RetrievalResult | None = None,
        ism_result: ISMResult | None = None,
    ) -> ConfidenceScore:
        """评估修复置信度，返回 ConfidenceScore（不持久化）。

        Args:
            bug_report: BugReport ORM 对象或 dict。
            trajectory: Trajectory 对象或 dict 或 None。
            kb_context: KB 检索结果或 None。
            ism_result: BB001 ISM 评估结果（可选，复用 info 维度评分）。

        Returns:
            ConfidenceScore 对象（内存中，调用方负责持久化）。
        """
```

### Q2：dim_info_completeness 计算规则？

优先级：
1. 若 `ism_result` 非 None → `dim_info_completeness = ism_result.score`（复用 BB001 LLM 精细评估）。
2. 否则 → 规则简化版（检查 BugReport 字段）：
   - 有 reproduction_steps / raw_report 含步骤 → +0.3
   - 有 version_code / device_model → +0.2
   - 有 stacktrace / logs → +0.3
   - 有 expected_behavior → +0.2
   - 总分 clamp [0, 1]

### Q3：dim_verification_feasibility 计算规则？

从 trajectory 状态：
- 有 confirmed hypothesis（`is_rootcause=True` 或 `status="confirmed"`）→ 基线 0.6
- 有 expected_signal 命中证据（confirming_evidence 非空）→ +0.2
- 无 falsifying_signal → +0.1
- 无 overturning_signal → +0.1
- `trajectory=None` → 0.3（低分兜底，无验证证据）
- 总分 clamp [0, 1]

### Q4：dim_patternability 计算规则？

见 IN scope 第 4 点（KB 模式命中加成），纯基于 `kb_context` 的 pattern 层条目统计：
- degraded / None → 0.2
- 有 KB 无 pattern → 0.4
- pattern 命中 1 条 → top1 similarity
- pattern 命中 >= 2 条 → min(top1 + 0.1, 1.0)

### Q5：rationale 构造？

```python
rationale = (
    f"dim_info={d1:.2f}, dim_verify={d2:.2f}, dim_pattern={d3:.2f}, "
    f"avg={score:.2f} → Tier {tier} "
    f"({tier_reason})"
)
```
其中 `tier_reason` 根据 Tier 分支：
- Tier 1: "all dims >= 0.7"
- Tier 2: "avg >= 0.5, no dim < 0.3"
- Tier 3: "avg >= 0.3"
- Tier 4: "avg < 0.3"

### Q6：kb_pattern_hit 字段格式？

```python
kb_pattern_hit = {
    "layer": "pattern",
    "top1_similarity": float,  # pattern 层 top1 similarity（无命中时 None）
    "hit_count": int,          # pattern 层命中条数
    "degraded": bool,          # kb_context.degraded
}
```
`kb_context=None` 时 `kb_pattern_hit=None`。

### Q7：阈值常量定义？

```python
# Tier 分级阈值（协商确定，参数化待校准）
TIER1_DIM_THRESHOLD: float = 0.7       # Tier1: 三维均 >= 此值
TIER2_AVG_THRESHOLD: float = 0.5       # Tier2: 三维平均 >= 此值
TIER2_DIM_FLOOR: float = 0.3           # Tier2: 无维度 < 此值
TIER3_AVG_THRESHOLD: float = 0.3       # Tier3: 三维平均 >= 此值

# KB pattern 维度打分
KB_PATTERN_BONUS: float = 0.1          # pattern 命中 >= 2 条的加成
KB_DEGRADED_PATTERN_SCORE: float = 0.2  # KB 降级时的 pattern 维度低分
KB_NO_PATTERN_HIT_SCORE: float = 0.4   # 有 KB 但无 pattern 命中的中低分
```
