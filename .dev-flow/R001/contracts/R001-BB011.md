## 任务边界

### 做什么（IN scope）

1. **新建 `agent/diagnosis/reflow_manager.py`**：ReflowManager 类——封装回流判定逻辑，管理两条回流路径（gap_pending 补齐 / regression-feedback 回流），产出 `bug.reflowed` 事件供 ORB01 监听重跑主链。事件驱动解耦，不直接调 ORB01。

2. **路径 A：gap_pending 补齐回流（`trigger_by_gap_fixed`）**：BugReport 处于 gap_pending 状态，当关联 Gap（linked_gap_id）被补齐（状态变 resolved）→ 发 `bug.reflowed` 事件，携带 trigger_path="gap_fixed"。

3. **路径 B：regression-feedback 回流（`trigger_by_regression`）**：BugReport 的 regression-feedback outcome=regression + 当前状态为 concluded/reflected → 发 `bug.reflowed` 事件，携带 trigger_path="regression_feedback"。语义：已结束/反思的 bug 出现回归信号，需重新排查。

4. **reflow_count 管理（`_check_reflow_limit`）**：从 BugReport.reflow_count 读取当前值，自增后判断是否超限。超限（默认 3 次）→ 不发 `bug.reflowed` 事件，返回 wont_reflow 信号（trigger_path="limit_exceeded"），由 ORB01 将 BugReport 状态置为 wont_reflow 转人工处理（AP-1）。本任务不直接修改 BugReport 状态。

5. **事件发布（`_publish_reflow_event`）**：通过 EventBus（INF07）发布 `bug.reflowed` 事件。EventBus=None 时降级（logging.warning + 事件仅记录到返回值，不阻断逻辑）。

6. **ReflowEvent dataclass**：事件载荷结构——bug_report_id / reflow_count（自增后值）/ trigger_path（"gap_fixed" | "regression_feedback" | "limit_exceeded"）/ linked_gap_id（路径 A 携带）/ regression_signal（路径 B 携带，可选）。

7. **回流路径判定（`determine_reflow_path`）**：根据 BugReport 当前状态 + 触发信号判定走路径 A 还是路径 B：
   - gap_pending + gap 补齐信号 → 路径 A
   - concluded/reflected + regression outcome → 路径 B
   - 其他状态 → 不回流（返回 ReflowResult(skipped=True)）

8. **单元测试**：`tests/unit/diagnosis/test_reflow_manager.py`，全 mock（EventBus / BugReport），覆盖路径 A / 路径 B / reflow_count 超限 / 事件载荷 / EventBus 降级 / 路径判定。

### 不做什么（OUT of scope）

- **不直接调 ORB01（Orchestrator）**：BB011 只产 `bug.reflowed` 事件，ORB01 监听该事件后决定是否重跑主链。事件驱动解耦是核心设计约束。
- **不持久化 BugReport**：本任务不写 BugReport.reflow_count / BugReport.status。reflow_count 自增后由 ORB01 持久化；wont_reflow 状态由 ORB01 置。本任务返回信号（ReflowResult），由调用方执行持久化。
- **不实现 EventBus 基础设施**：EventBus 由 INF07 提供，本任务通过依赖注入接收 EventBus 实例。不实现事件序列化 / 重试 / 持久化等基础设施逻辑。
- **不实现 regression-feedback 检测**：regression outcome 的检测由 ORB01 在修复验证 / 回归测试后判定，本任务接收已判定的 regression 信号作为输入。
- **不实现 Gap 补齐检测**：Gap 状态变 resolved 由 BF008 GapStore 管理，本任务接收 gap_fixed 信号作为输入（由 ORB01 在 Gap 补齐后调用）。
- **不做 async 接口**：所有方法为同步 `def`（纯判定 + 同步发事件）。

## 关键决策

### Q1：事件如何发送？

**决策：通过 EventBus（INF07）发布 `bug.reflowed` 事件。**

理由：
1. 事件驱动解耦是核心架构约束——BB011 不应直接调 ORB01（Orchestrator），否则形成紧耦合。
2. INF07 EventBus 提供 publish/subscribe 机制，ORB01 订阅 `bug.reflowed` 事件后自主决定是否重跑主链。
3. EventBus=None 时降级（logging.warning），逻辑判定仍完成，ReflowResult 返回正确结论——调用方可感知事件丢失并后续补偿。

### Q2：reflow_count 从哪读？

**决策：从 BugReport.reflow_count 读，自增后由调用方（ORB01）持久化。**

理由：
1. BB011 不持久化 BugReport（OUT of scope），避免写操作分散。
2. ReflowManager 内部 `_check_reflow_limit` 读取 bug_report.reflow_count → 自增 → 判断是否超限 → 返回自增后值。
3. ORB01 收到 ReflowResult 后，将 reflow_count 持久化到 BugReport（无论是否超限，count 都要更新）。
4. 并发安全：ORB01 负责 BugReport 锁/版本控制，本任务不做并发处理。

### Q3：wont_reflow 状态由谁置？

**决策：本任务返回 wont_reflow 信号（ReflowResult.wont_reflow=True），由 ORB01 置 BugReport.status=wont_reflow。**

理由：
1. BB011 不直接改 BugReport 状态（OUT of scope），职责清晰。
2. wont_reflow 是 BugReport 状态机的一个终态（AP-1：转人工），状态迁移由 ORB01 统一管理。
3. ReflowResult.wont_reflow=True 作为信号，ORB01 判断后执行 status 迁移 + 触发人工通知。

### Q4：路径 A 和路径 B 可以同时触发吗？

**决策：不可以。两条路径互斥，优先路径 A（gap_fixed）> 路径 B（regression）。**

理由：
1. gap_pending 状态的 BugReport 不会同时处于 concluded/reflected（状态互斥），所以两路径天然互斥。
2. `determine_reflow_path` 返回单一路径标识，不存在同时返回两条路径的情况。
3. 如果 ORB01 先收到 gap_fixed 信号再收到 regression 信号（或反之），由 ORB01 负责去重/排序，本任务每次调用只处理一个触发。

### Q5：max_reflow_count 默认值为什么是 3？

**决策：默认 3 次，可 config 覆盖。**

理由：
1. AP-1 设计原则：回流次数超限转人工，避免无限循环。
2. 3 次是一个保守上限：第 1 次回流可能是补齐缺口，第 2 次可能是回归修复，第 3 次仍失败通常意味着系统排查能力不足，应转人工介入。
3. 构造函数参数 `max_reflow_count` 允许 ORB01 根据项目配置覆盖（如某些项目允许 5 次回流）。

## 实现要点

### 类设计

```python
from __future__ import annotations

from dataclasses import dataclass, field
from typing import Any, Optional
import logging

logger = logging.getLogger(__name__)


@dataclass
class ReflowEvent:
    """回流事件载荷（发布到 EventBus）。"""
    bug_report_id: str
    reflow_count: int
    trigger_path: str  # "gap_fixed" | "regression_feedback" | "limit_exceeded"
    linked_gap_id: Optional[str] = None
    regression_signal: Optional[dict] = None

    event_type: str = field(default="bug.reflowed", init=False, repr=False)


@dataclass
class ReflowResult:
    """回流判定结果（返回给调用方 ORB01）。"""
    reflowed: bool
    trigger_path: str
    wont_reflow: bool = False
    reflow_count: int = 0
    skipped: bool = False
    reason: Optional[str] = None
    event: Optional[ReflowEvent] = None


class ReflowManager:
    """回流管理器：判定回流路径 + 产 bug.reflowed 事件。

    事件驱动解耦——不直接调 ORB01，只通过 EventBus 发布事件。
    """

    def __init__(
        self,
        *,
        event_bus: Optional[Any] = None,  # INF07 EventBus
        max_reflow_count: int = 3,
    ) -> None:
        self._event_bus = event_bus
        self._max_reflow_count = max_reflow_count

    def trigger_by_gap_fixed(
        self,
        bug_report: Any,  # BugReport（含 status / reflow_count / linked_gap_id）
        gap_id: str,
    ) -> ReflowResult:
        """路径 A：gap_pending 补齐 → 发 bug.reflowed 事件。"""
        ...

    def trigger_by_regression(
        self,
        bug_report: Any,
        regression_signal: dict,
    ) -> ReflowResult:
        """路径 B：concluded/reflected + regression → 发 bug.reflowed 事件。"""
        ...

    def determine_reflow_path(
        self,
        bug_report: Any,
        gap_fixed: Optional[str] = None,
        regression_signal: Optional[dict] = None,
    ) -> Optional[str]:
        """判定回流路径（gap_fixed / regression_feedback / None）。"""
        ...

    def _check_reflow_limit(self, bug_report: Any) -> bool:
        """reflow_count 超限检查；返回 True 表示超限。"""
        ...

    def _publish_reflow_event(self, event: ReflowEvent) -> None:
        """通过 EventBus 发布事件（None 时降级）。"""
        ...

    @staticmethod
    def _build_event(
        bug_report: Any,
        reflow_count: int,
        trigger_path: str,
        linked_gap_id: Optional[str] = None,
        regression_signal: Optional[dict] = None,
    ) -> ReflowEvent:
        """构造 ReflowEvent。"""
        ...
```

### 回流路径判定逻辑

| BugReport.status | gap_fixed 信号 | regression_signal | 结果路径 |
|------------------|---------------|-------------------|---------|
| gap_pending | 非 None | - | gap_fixed |
| concluded | - | 非 None | regression_feedback |
| reflected | - | 非 None | regression_feedback |
| proposed/verifying/fixing | 任意 | 任意 | None（不可回流） |
| gap_pending | None | - | None（缺触发） |
| concluded | - | None | None（缺触发） |

### reflow_count 超限逻辑

```python
def _check_reflow_limit(self, bug_report) -> bool:
    current_count = bug_report.reflow_count
    return current_count >= self._max_reflow_count
    # 注意：当前 count >= max 时超限（第 max+1 次回流被拒）
```

| 风险 | 影响 | 降级 |
