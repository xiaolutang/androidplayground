## 任务边界

### 做什么（IN scope）

1. **新建 `agent/diagnosis/reflection_agent.py`**：ReflectionAgent 类——读 trajectory（含 refuted/overturned 假设）→ LLM 提取 negative_knowledge + 命中线索 → 写 raw_trajectory / negative_knowledge 层。严格守护 INV-3：**禁写 pattern 层**。

2. **读 trajectory（`_collect_hypotheses`）**：从 Trajectory 收集所有 hypothesis（含 confirmed / refuted / overturned），完整传递给 LLM 做反思。refuted/overturned 假设是 negative_knowledge 的主要来源。

3. **LLM 提取 negative_knowledge（`_extract_negative_knowledge`）**：调 LLMGateway(reflection→glm-5.1) 对 refuted/overturned 假设提取 negative_knowledge——"为什么这条假设被否定了"、"什么情况下不应该走这条路径"。返回结构化 negative_knowledge 条目列表。

4. **命中线索提取（`_extract_hit_clues`）**：从成功路径（confirmed → fixing 成功）提取关键决策记录，写入 raw_trajectory 层。记录"哪条假设导致了成功修复"、"什么信号是关键判据"。

5. **KB 写入——negative_knowledge 层（`_write_negative_knowledge`）**：调 `KBRetriever.add_negative_knowledge(content, source_hypothesis_id, confidence)` 逐条写入。content 为 LLM 提取的负面知识文本，source_hypothesis_id 为对应的 refuted/overturned hypothesis_id，confidence 为 LLM 返回的置信度。

6. **KB 写入——raw_trajectory 层（`_write_raw_trajectory`）**：调 `KBRetriever.add_raw_trajectory(...)` 写入命中线索（成功路径关键决策）。

7. **INV-3 守护**：类中**无** `add_pattern` 方法，`available_operations` 属性返回 `["add_negative_knowledge", "add_raw_trajectory"]`——从代码结构上保证不可能写 pattern 层。

8. **LLM 失败降级（`_safe_llm_call`）**：LLMGateway 调用失败（超时 / API 错误 / 解析失败）→ 捕获异常 + logging.warning + 跳过 negative_knowledge 写入（不写部分结果，避免误导）。raw_trajectory 层的命中线索不依赖 LLM（从 Trajectory 结构化数据直接提取），仍正常写入。

9. **ReflectionResult dataclass**：反思结果结构——extracted_count（LLM 提取的 negative_knowledge 条数）/ written_count（成功写入 KB 的条数）/ skipped_reason（跳过原因，如 LLM 失败 / 无 refuted 假设）。

10. **单元测试**：`tests/unit/diagnosis/test_reflection_agent.py`，全 mock（LLMGateway / KBRetriever / Trajectory），覆盖 negative_knowledge 提取 / 命中线索 / INV-3 守护 / LLM 失败降级 / ReflectionResult 结构。

### 不做什么（OUT of scope）

- **禁写 pattern 层（INV-3）**：本任务**不可**调用 KBRetriever.add_pattern 或任何写 pattern 层的方法。pattern 层唯一写入入口是 BB015（人工修复录入器），BB013 写 pattern 是 INV-3 违规。
- **不实现 LLM 调用基础设施**：LLMGateway 由 INF04 提供，本任务通过依赖注入接收 LLMGateway 实例，调 `gateway.complete(model="glm-5.1", messages=[...])` 或等价接口。不实现 API 客户端 / 重试 / 缓存。
- **不做 KB 层级选择决策**：本任务固定写 negative_knowledge + raw_trajectory 两层，不做"是否值得写入"的智能判断——只要 LLM 提取到了 negative_knowledge 就写。
- **不触发回流**：反思完成后不调 ReflowManager（BB011）。反思与回流是独立流程，由 ORB01 编排（ORB01 在 bug concluded/reflected 后调 BB013 做反思，反思完成后 ORB01 决定是否触发回流）。
- **不持久化 Trajectory / Hypothesis**：本任务只读 Trajectory，不写。Trajectory 持久化由 ORB01 负责。
- **不做 async 接口**：所有方法为同步 `def`（LLM 调用为同步阻塞，MVP 阶段不做 async LLM）。

## 验收标准（可测试）

### AC-1：读 trajectory（所有 hypothesis，含 refuted/overturned）

- **断言**：`_collect_hypotheses(trajectory)` 返回 trajectory 中所有 hypothesis 列表（含 confirmed / refuted / overturned 全部状态）。
- **断言**：refuted hypothesis 不被过滤——refuted 是 negative_knowledge 的核心来源，必须完整传递给 LLM。
- **断言**：overturned hypothesis（根因回退）同样被收集——overturning_signal 记录了推翻原因，是高价值负面知识。
- **断言**：空 trajectory（无 hypothesis）→ 返回空列表，后续 LLM 不调用，ReflectionResult(skipped_reason="no_hypotheses")。

### AC-2：LLMGateway(reflection→glm-5.1) 提取 negative_knowledge

- **断言**：`_extract_negative_knowledge(hypotheses)` 调 `llm_gateway.complete(model="glm-5.1", ...)` 或等价 INF04 接口。
- **断言**：LLM prompt 包含 refuted/overturned hypothesis 的 content + falsifying_signal / overturning_signal（提供否定证据上下文）。
- **断言**：LLM 返回结构化结果（JSON / list of dict），每条含 content + source_hypothesis_id + confidence。
- **断言**：confirmed hypothesis 不作为 negative_knowledge 来源（它们是正面知识，不写入 negative_knowledge 层）。

### AC-3：命中线索（成功路径关键决策记录到 raw_trajectory）

- **断言**：`_extract_hit_clues(trajectory)` 从 confirmed hypothesis → fixing 成功的路径提取关键决策。
- **断言**：命中线索写入 KBRetriever.add_raw_trajectory（不依赖 LLM，从 Trajectory 结构化数据直接提取）。
- **断言**：命中线索内容含：root_hypothesis_id / confirmed_evidence / fixing_action_summary / success_signal。
- **断言**：无 confirmed hypothesis（诊断失败 / 转缺口）→ 不写 raw_trajectory（无线索可记录）。

## 关键决策

### Q1：触发时机？

**决策：由 ORB01 在 bug concluded/reflected 后调用 ReflectionAgent.reflect(trajectory)。**

理由：
1. 反思发生在诊断结束之后（bug 状态为 concluded 或 reflected），此时 trajectory 已完整。
2. ORB01（Orchestrator）负责编排：诊断结束 → 调 BB013 反思 → 反思完成 → 决定是否触发回流（调 BB011）。
3. 本任务不自主触发（无内部调度），纯被动等待 ORB01 调用。

### Q2：写哪些层？

**决策：negative_knowledge（refuted/overturned 假设）+ raw_trajectory（成功路径命中线索）。**

理由：
1. negative_knowledge 层：记录"哪些假设被否定了、为什么"——供后续 BugReport 的 BB004 negate_and_prune 预剪枝使用。
2. raw_trajectory 层：记录"成功路径的关键决策"——供 BB005 根因定位参考（相似症状可复用成功路径）。
3. **不写 pattern 层（INV-3）**：pattern 是"确定的修复模板"，需人工审核确认（BB015），反思 agent 自动提取的知识可信度不足以直接写 pattern。

### Q3：INV-3 守护实现？

**决策：代码结构保证——类中无 add_pattern 方法 + available_operations 白名单。**

理由：
1. 最直接的守护：ReflectionAgent 类不提供 add_pattern 方法，从 API 层面不可能写 pattern。
2. `available_operations` 属性返回白名单 `["add_negative_knowledge", "add_raw_trajectory"]`，供外部审计/校验。
3. 即使未来误加 add_pattern 调用，available_operations 测试断言会失败（回归保护）。
4. 这与 BB015 形成对比——BB015 是唯一有 add_pattern 方法/调用的模块（INV-3/AP-3）。

### Q4：LLM 返回结果如何校验？

**决策：基本结构校验（必须有 content + source_hypothesis_id），不做语义校验。**

理由：
1. LLM 返回的 negative_knowledge 是自然语言文本，无法自动校验语义正确性。
2. 结构校验：每条必须有 content（非空字符串）、source_hypothesis_id（存在于 trajectory 中）、confidence（0.0-1.0）。
3. 缺字段或格式错 → 该条丢弃 + logging.warning，不影响其他条目。
4. 语义质量依赖 LLM 模型能力（glm-5.1）+ prompt 工程，不在本任务 scope。

### Q5：raw_trajectory 写入为什么不依赖 LLM？

**决策：命中线索从 Trajectory 结构化数据直接提取，不走 LLM——避免 LLM 失败导致正面知识丢失。**

理由：
1. raw_trajectory 记录的是事实（哪条假设 confirmed、什么信号匹配、修复用了什么 action），这些信息在 Trajectory 中已结构化存在。
2. LLM 的价值在于从 refuted 假设中"概括"负面知识（需要推理）；命中线索是直接提取（不需要推理）。
3. LLM 失败时 negative_knowledge 可跳过（降级可接受），但命中线索丢失会降低后续诊断效率——因此命中线索走结构化提取，不走 LLM。

## 实现要点

### 类设计

```python
from __future__ import annotations

from dataclasses import dataclass
from typing import Any, Optional
import logging

logger = logging.getLogger(__name__)


@dataclass
class NegativeKnowledgeItem:
    """LLM 提取的单条 negative_knowledge。"""
    content: str
    source_hypothesis_id: str
    confidence: float


@dataclass
class HitClue:
    """命中线索（成功路径关键决策）。"""
    root_hypothesis_id: str
    confirmed_evidence: dict
    fixing_action_summary: str
    success_signal: dict


@dataclass
class ReflectionResult:
    """反思结果。"""
    extracted_count: int
    written_count: int
    skipped_reason: Optional[str] = None
    raw_trajectory_written: bool = False


class ReflectionAgent:
    """反思 agent：读 trajectory → LLM 提取 negative_knowledge + 命中线索。

    INV-3 守护：仅写 negative_knowledge / raw_trajectory 层，禁写 pattern。
    """

    # INV-3 守护：白名单操作（不含 add_pattern）
    AVAILABLE_OPERATIONS = frozenset({"add_negative_knowledge", "add_raw_trajectory"})

    def __init__(
        self,
        *,
        llm_gateway: Any,  # INF04 LLMGateway
        kb_retriever: Optional[Any] = None,  # BF005 KBRetriever
        model: str = "glm-5.1",
    ) -> None:
        self._llm_gateway = llm_gateway
        self._kb_retriever = kb_retriever
        self._model = model

    @property
    def available_operations(self) -> list[str]:
        """返回可用写入操作白名单（INV-3 守护）。"""
        return sorted(self.AVAILABLE_OPERATIONS)

    def reflect(self, trajectory: Any) -> ReflectionResult:
        """主入口：反思 trajectory → 写 negative_knowledge + raw_trajectory。"""
        ...

    def _collect_hypotheses(self, trajectory: Any) -> list[Any]:
        """收集所有 hypothesis（含 refuted/overturned）。"""
        ...

    def _extract_negative_knowledge(
        self, hypotheses: list[Any]
    ) -> list[NegativeKnowledgeItem]:
        """LLM 提取 negative_knowledge（仅从 refuted/overturned 假设）。"""
        ...

    def _extract_hit_clues(self, trajectory: Any) -> list[HitClue]:
        """提取命中线索（成功路径关键决策，不走 LLM）。"""
        ...

    def _write_negative_knowledge(
        self, items: list[NegativeKnowledgeItem]
    ) -> int:
        """逐条写入 negative_knowledge 层；返回成功写入条数。"""
        ...

    def _write_raw_trajectory(self, clues: list[HitClue]) -> bool:
        """写入 raw_trajectory 层命中线索。"""
        ...

    def _safe_llm_call(self, messages: list[dict]) -> Optional[Any]:
        """LLM 调用 + 失败降级（捕获 + warning + 返回 None）。"""
        ...

    # INV-3 守护：显式无 add_pattern 方法
    # def add_pattern(self, ...) -> NotImplementedError  # 不定义，从结构上排除
```

]
