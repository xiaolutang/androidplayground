## 任务边界

### 做什么（IN scope）

1. **抽象基类 `BugReportAdapter`**（`agent/intake/bug_report_adapter.py`，当前为空文件待实现）：
   - ABC，定义 `normalize(raw: dict) -> BugReport` 抽象方法签名。
   - 定义 `extract_external_id(raw: dict) -> str | None` 抽象方法（幂等 key 提取，见 AC-5）。
   - 提供 INV-1 守护的共享校验逻辑（`_validate_version_code(version_code: str | None) -> None`，缺失抛 `VersionCodeMissingError`）。

2. **Sentry 适配器**（`agent/intake/adapters/sentry_adapter.py`，当前为空文件待实现）：
   - `SentryAdapter(BugReportAdapter)`，完整实现 `normalize` + `extract_external_id`。
   - 解析 Sentry webhook payload（参考 https://docs.sentry.io/product/integrations/integration-platform/webhooks/ ）。
   - 字段映射见 AC-7。

3. **Bugly 适配器占位**（`agent/intake/adapters/bugly_adapter.py`，当前为空文件待实现）：
   - `BuglyAdapter(BugReportAdapter)`，`normalize` / `extract_external_id` 均抛 `NotImplementedError("Bugly adapter not implemented yet; see D8 roadmap")`。

4. **幂等 key 提取接口**（抽象基类层面）：
   - `extract_external_id(raw) -> str | None`：从原始 payload 提取平台级唯一 event_id（Sentry 的 `event.event_id`）。
   - 本任务**只提供提取接口**，不实现存储查询。实际幂等查询（exists_by_external_id）由 FF001 router 调用 BugReportStore 实现，BF001 提供接口契约（见实现要点 Q3）。

5. **INV-1 versionCode 必携守护**（共享逻辑）：
   - `normalize` 归一化后，若 `version_code` 为空/缺失 → 抛 `VersionCodeMissingError`（INV-1 强制；不静默降级）。
   - 异常类定义在 `agent/intake/bug_report_adapter.py`。

6. **BugReport schema 新增 `external_id` 字段**（agent/schemas/bug_report.py）：
   - 新增 `external_id: Mapped[str | None]`（nullable=True，加唯一索引意向字段，但 MVP 不加 DB unique constraint——约束由 FF001 router 查询实现）。
   - 用途：存储 Sentry event_id，供 FF001 router 做幂等查询（`WHERE source_platform=? AND external_id=?`）。
   - **协商说明**：原 BugReport schema 无此字段，analysis 4.1 表未列。本任务因幂等需求新增，属 schema 演进，已在 AC-7 标注。

7. **单元测试**（fixture 数据，无 DB 调用、无网络调用）：
   - Sentry payload fixture（最小可用：含 event_id / release / dist / exception.values[].stacktrace.frames）。
   - 覆盖见 AC-8。

### 不做什么（OUT of scope）

- **不实现 FastAPI router**（`POST /webhook/{platform}` 端点）：FF001 report_router 负责 HTTP 接入、调 adapter.normalize、调 BugReportStore.exists_by_external_id 做幂等查询、返回 409。BF001 只提供被调用的 adapter + 异常类。
- **不实现真实 Sentry webhook 集成测试**：用本地 fixture（JSON dict）模拟 payload，不调 Sentry 服务、不做 httpx 集成。
- **不实现 BugReportStore / DB 查询**：exists_by_external_id 接口契约在 BF001 定义（docstring / Protocol），实现归 FF001 或 SCH01 扩展任务。
- **不实现 Bugly / Crashlytics 真实适配器**：Bugly 仅占位（NotImplementedError）；Crashlytics 不在本任务（D8 roadmap 后续）。
- **不改 14 态状态机枚举**：BugReport.status 只消费 `BugReportStatus.RECEIVED.value`，不新增/修改枚举。
- **不实现 Pydantic DTO**（webhook 请求/响应模型）：归 FF001 router 任务。
- **不加 DB migration**：external_id 字段加到 SQLAlchemy model；实际建表/迁移由 DB 初始化脚本或后续 INF 任务负责（当前无 alembic，建表走 `Base.metadata.create_all`）。

## 验收标准（可测试）

### AC-1：抽象基类 BugReportAdapter

- **断言**：`BugReportAdapter` 为 ABC（`abc.ABC`），不可实例化（`BugReportAdapter()` 抛 `TypeError`）。
- **断言**：抽象方法 `normalize(self, raw: dict) -> BugReport`（子类必须实现）。
- **断言**：抽象方法 `extract_external_id(self, raw: dict) -> str | None`（子类必须实现）。
- **断言**：共享校验方法 `_validate_version_code(self, version_code: str | None) -> None`：`version_code` 为 None / 空字符串 / 仅空白 → 抛 `VersionCodeMissingError`。
- **断言**：`VersionCodeMissingError` 继承 `Exception`，message 含 "INV-1" 与 "version_code"（便于日志检索）。

### AC-2：Sentry 适配器 normalize

- **断言**：`SentryAdapter().normalize(raw)` 输入 Sentry webhook payload dict，返回 `BugReport` 实例（内存对象，未持久化）。
- **断言**：返回的 `BugReport.status == BugReportStatus.RECEIVED.value`（"received"，见 AC-6）。
- **断言**：返回的 `BugReport.source_platform == "sentry"`。
- **断言**：返回的 `BugReport.version_code` / `version_name` 从 Sentry release/dist 解析（见 AC-7）。
- **断言**：`normalize` 内部调 `_validate_version_code`，versionCode 缺失时抛 `VersionCodeMissingError`（不返回半成品 BugReport）。

### AC-3：Bugly 占位

- **断言**：`BuglyAdapter(BugReportAdapter)` 可实例化（不抛错——占位类本身可构造，方法调用才抛）。
- **断言**：`BuglyAdapter().normalize({})` 抛 `NotImplementedError`，message 含 "Bugly"。
- **断言**：`BuglyAdapter().extract_external_id({})` 抛 `NotImplementedError`。
- **断言**：BuglyAdapter 继承 BugReportAdapter（isinstance 检查通过）。

### AC-4：INV-1 versionCode 守护

- **断言**：Sentry payload 中 release/dist 均缺失 → `normalize` 抛 `VersionCodeMissingError`。
- **断言**：Sentry payload 中 release 存在但解析后 version_code 为空字符串 → 同样抛 `VersionCodeMissingError`。
- **断言**：`VersionCodeMissingError` 不被 adapter 吞掉（直接上抛给调用方 FF001 router，router 负责转 400 响应——但转响应逻辑不在 BF001）。
- **断言**：守护逻辑在基类 `_validate_version_code`，Sentry 子类复用不重复实现（DRY）。

### AC-5：幂等 key 提取接口

- **断言**：`SentryAdapter().extract_external_id(raw)` 从 `raw["event"]["event_id"]` 提取（Sentry webhook payload 结构），返回 UUID 字符串。
- **断言**：`event_id` 缺失（payload 无 `event.event_id`）→ 返回 `None`（不抛错；调用方 FF001 决定是否拒绝无 event_id 的上报）。
- **断言**：`extract_external_id` 是纯提取，不查 DB、不写存储（接口职责单一）。
- **断言**：BF001 在 `bug_report_adapter.py` 模块 docstring 或 Protocol 中声明幂等查询契约：调用方应实现 `exists_by_external_id(source_platform: str, external_id: str) -> bool`，BF001 不实现此方法。

### AC-6：状态归一化

- **断言**：`SentryAdapter().normalize(raw).status == "received"`（硬编码归一化为 received，14 态的初始态）。
- **断言**：归一化不依赖 raw payload 中的任何 status 字段（Sentry 无此概念；status 由 agent 系统定义）。
- **断言**：引用 `BugReportStatus.RECEIVED.value`（不硬编码字符串 "received"，避免枚举重构时漂移）。

### AC-7：字段映射

Sentry payload → BugReport 字段映射：

| Sentry payload 路径 | BugReport 字段 | 说明 |
|---------------------|---------------|------|
| `event.event_id` | `external_id`（新增字段） | 幂等 key |
| `event.release` | `version_code` | INV-1 必携；release 约定为 versionCode |
| `event.dist` | `version_name` | dist 约定为 versionName（可选，缺失时 version_name=None 但 version_code 必须有） |
| `event.exception.values[0].stacktrace.frames` | `raw_report`（JSON dict，存原始 stacktrace 结构） | 归一化后原始数据留存 |
| 整个 raw payload | `raw_report` 同时保留完整 raw（key: `_raw_sentry_payload`） | 审计/回溯用 |
| （常量） | `source_platform = "sentry"` | 平台标识 |
| （常量） | `status = "received"` | 见 AC-6 |

- **断言**：`normalize` 返回的 `BugReport.external_id == raw["event"]["event_id"]`。
- **断言**：`version_code` 从 `raw["event"]["release"]` 提取；release 缺失 → 触发 AC-4 守护抛错。
- **断言**：`raw_report` 非空 dict（含 stacktrace 与完整 payload 两份留存）。
- **断言**：`id` 字段不在此填充（由 FF001 router 或持久化层生成 UUID；normalize 只产业务字段，不产主键）。

## 实现要点

### Q1：抽象基类位置？

**决策：`agent/intake/bug_report_adapter.py`**（已存在空文件）。

目录结构：
```
agent/intake/
├── __init__.py
├── bug_report_adapter.py          # ABC + VersionCodeMissingError
└── adapters/
    ├── __init__.py
    ├── sentry_adapter.py           # SentryAdapter（完整实现）
    └── bugly_adapter.py            # BuglyAdapter（NotImplementedError 占位）
```

### Q2：Sentry payload 字段参考？

Sentry webhook payload 结构（参考 https://docs.sentry.io/product/integrations/integration-platform/webhooks/ ）：
- `event.event_id`：UUID，平台唯一（幂等 key）
- `event.release`：发布版本（约定为 Android versionCode）
- `event.dist`：发布 dist（约定为 versionName）
- `event.exception.values[].stacktrace.frames`：堆栈帧数组

MVP 只解析上述核心字段；其余 Sentry 字段（tags / contexts / breadcrumbs）整体存入 `raw_report` 留存，不做结构化解析。

### Q3：幂等如何实现？

**决策：BF001 只提供 event_id 提取（external_id），实际幂等查询由 FF001 router 实现。**

分工：
- BF001 `SentryAdapter.extract_external_id(raw) -> str | None`：纯提取，从 payload 拿 event_id。
- BF001 在基类模块声明 Protocol / docstring 契约：调用方（FF001）应实现：
  ```python
  def exists_by_external_id(source_platform: str, external_id: str) -> bool: ...
  ```
- FF001 router 流程：`adapter.extract_external_id(raw)` → `store.exists_by_external_id(platform, eid)` → 已存在返回 409 → 不存在则 `adapter.normalize(raw)` → 持久化。

理由：BF001 是 business layer（无 DB 依赖），存储查询归 data layer（BugReportStore）+ API layer（router）。解耦便于单元测试（BF001 不碰 DB）。

### Q4：external_id 为何需要新增 schema 字段？

原 BugReport schema（SCH01）无 external_id。幂等需要平台级唯一 key 落库可查。方案对比：
- **方案 A（采纳）**：BugReport 新增 `external_id` 字段 + `source_platform` 组合查询。简单直接，查询 `WHERE source_platform=? AND external_id=?`。
- 方案 B（否决）：单独建 `webhook_event_log` 表。过度设计，MVP 不需要。

external_id nullable=True（允许无 event_id 的上报进入，由 FF001 决定是否拒绝）。不加 DB unique constraint（因为 nullable + 多平台组合，constraint 由查询逻辑保证）。

### Q5：BugReport 构造方式？

`normalize` 返回 `BugReport(...)` 内存对象，**不触发 DB session**（不调 `db.session.add`）。字段用构造器传参：

```python
return BugReport(
    source_platform="sentry",
    external_id=event_id,
    version_code=version_code,
    version_name=version_name,
    raw_report={"stacktrace": ..., "_raw_sentry_payload": raw},
    status=BugReportStatus.RECEIVED.value,
)
# id / completeness_score / created_at 等不在此填，由持久化层补
```
