## 任务边界

### 做什么（IN scope）

1. **新建 `agent/reproduce/` 包下 5 个文件**（当前均为空，待实现）：
   - `adb_tools.py`：ADB 工具层（双模式共用）
   - `emulator_pool.py`：模拟器启停/分配
   - `apk_installer.py`：APK 安装/启动/卸载
   - `screenshot_collector.py`：截图采集
   - `reproduce_runner.py`：确定性复现脚本执行器

2. **adb_tools（BF002.1，双模式共用）**：对 INF05 `ADBClient` 做 thin 函数封装，暴露统一工具接口给复现模式（确定性脚本）与探测模式（agent tool-calling）共用。设计决策见「实现要点」Q1。

3. **emulator_pool（BF002.3）**：单模拟器 MVP 管理（启停/分配/释放）。subprocess 启动 emulator 进程，轮询 `sys.boot_completed` 检测 boot 完成。启动失败抛 `EmulatorStartError`。

4. **apk_installer（BF002.3）**：install / launch(`am start`) / uninstall / get_installed_version（`dumpsys package`）。install 复用 `ADBClient.install_apk`，其余走 `adb shell` 子动作。

5. **screenshot_collector（BF002.3）**：从 `ADBClient.screenshot()` 拿 PNG bytes，封装两种产出形态：保存到磁盘（`file://` URL）或 in-memory（base64 data URL）。BF003 视觉决策消费 `image_url`。

6. **reproduce_runner（BF002.2，复现模式）**：输入 Playbook 复现脚本（list[dict]，每条含 `action / params / expected_signal`），确定性顺序调 `adb_tools` 执行，每步采集 `ReproStep`（含 screenshot_ref + actual_signal）。BF003 不参与本路径。

7. **信号采集（最小 logcat 抓取）**：因 BF004 `logcat_listener.py` 尚未实现（空文件），reproduce_runner 自带一次性 logcat 抓取（`adb logcat -d` 一次性 dump，非长连接流式），匹配预期 signal pattern；BF004 实现后由其接管，本任务的最小实现保留为 fallback。

8. **启动失败转设施缺口**：emulator 启动失败（进程启动失败 / boot 超时）→ 调用 `GapStore.create({gap_type: 'facility', status 自动为 identified, description, linked_bug_ids: []})`（BF008 已实现），上抛 `EmulatorStartError` 由 Orchestrator 转 degraded 模式。

9. **单元测试 + 集成测试**：
   - 单元测试全 mock（ADBClient / subprocess / GapStore），覆盖工具层包装 + runner 流程逻辑 + emulator 启停 + 启动失败转缺口。
   - 集成测试放 `tests/integration_bf002/`，`@pytest.mark.skipif` 无 emulator 守护（沿用 INF05 skipif 模式），手动 `--run-emulator` 触发，不进主 CI。

### 不做什么（OUT of scope）

- **不改 INF05 `ADBClient` 既有接口**（6 动作签名 / `ADBResult` / 4 异常类保持不变）。BF002 只消费不修改 INF05。
- **不改 SCH02 `ReproStep` / `Signal` schema 字段名/类型**（直接消费；如 `actual_signal` 为 JSON 字段，本任务把抓到的信号快照嵌入 dict 写入）。
- **不实现探测/诱发模式（BB003 LangGraph agent loop）**：本任务只做复现模式（确定性脚本驱动）。BB003 探测模式会复用本任务的 `adb_tools` 工具层，但 agent loop / BF003 视觉决策不在 BF002 范围。
- **不实现 BF004 信号监听器**：本任务的最小 logcat 抓取仅为 reproduce_runner 内部 fallback，不替代 BF004 的四类信号（logcat/flutter_error/process/visual）完整监听体系。
- **不做多模拟器池并发**：MVP 单模拟器 + 串行（确定性）。emulator_pool 接口预留 `allocate/release`，但 MVP 实现只支持单实例（已启动的 device 复用，无并发分配）。
- **不做 async 接口**：同步 subprocess（与 INF05 风格一致）。复现脚本顺序执行，无并发需求。
- **不实现 ToolRegistry / agent tool 描述**（JSON Schema 工具描述）：BB003 探测模式会基于本任务的函数签名自行封装 tool_call 描述。BF002 只提供可调用的 Python 函数。
- **不实现 Playbook 复现脚本的生成**：复现脚本由 BB003 / 人工 / KB pattern 提供，BF002 只负责执行已给定的脚本。
- **不耦合 Orchestrator / BugReport 状态机**：reproduce_runner 输出 `list[ReproStep]`（内存对象），持久化时机由调用方（Orchestrator）决定。

## 验收标准（可测试）

### AC-1：adb_tools 工具层（封装 INF05）

- **断言**：`adb_tools.tap(client, x=100, y=200, device_id=None)` 内部调 `client.tap(100, 200)`，返回 `ADBResult`（透传 INF05 结果，不重新包装）。
- **断言**：六个函数 `tap / swipe / input_text / screenshot / install_apk / press_key` 签名与 INF05 `ADBClient` 对应方法参数对齐（`client` 为首参，其余参数透传）。
- **断言**：`swipe(client, x1, y1, x2, y2, duration_ms=300, device_id=None)` 默认 duration_ms=300（与 INF05 默认值一致）。
- **断言**：INF05 异常（`ADBConnectionError / ADBCommandError / ADBTimeoutError`）原样上抛，不在工具层吞掉（保持调用方可统一 `except ADBError`）。
- **断言**：函数模块无 class，纯函数；不持有 client 实例（client 由调用方注入，支持测试 mock）。

### AC-2：emulator_pool 模拟器管理

- **断言**：`EmulatorPool(avd_name, settings).start()` 启动 emulator 子进程（命令：`emulator -avd <name> -no-window -no-audio -no-snapshot`，subprocess.Popen 非阻塞），返回 device_id（从 `adb devices` 轮询拿到）。
- **断言**：`wait_boot_complete(device_id, timeout=120)` 轮询 `adb shell getprop sys.boot_completed`，返回 `"1"` 时返回 True；超时抛 `EmulatorBootTimeoutError`。
- **断言**：`allocate()` MVP 实现返回已启动的单 device_id（无并发分配；多次调用返回同一 id）。
- **release(device_id)` MVP 为 no-op（单实例不复用池语义，仅记录日志）。
- **断言**：`stop(device_id)` 调 `adb emu kill`（或 `kill` 子进程），并验证进程退出。
- **断言**：emulator 二进制解析（`emulator` 命令）：env `EMULATOR_BIN` → `$ANDROID_SDK/emulator/emulator`（macOS: `~/Library/Android/sdk/emulator/emulator`）→ `shutil.which("emulator")`，找不到抛 `EmulatorConfigError`。
- **断言**：进程启动失败（Popen 抛 FileNotFoundError / 进程立即退出 returncode != 0）→ 抛 `EmulatorStartError`。

### AC-3：apk_installer 安装/启动/卸载

- **断言**：`install(apk_path, device_id)` 内部调 `ADBClient.install_apk(apk_path, device_id=device_id)`，返回 `ADBResult`。
- **断言**：`launch(package, activity, device_id)` 调 `adb shell am start -n <package>/<activity>`，返回 `ADBResult`。
- **断言**：`uninstall(package, device_id)` 调 `adb uninstall <package>`，返回 `ADBResult`。
- **断言**：`get_installed_version(package, device_id)` 调 `adb shell dumpsys package <package>`，解析输出提取 `versionName`，未安装返回 None。
- **断言**：apk_path 不存在时由 INF05 `ADBCommandError` 上抛（不在本层重复校验）。

### AC-4：screenshot_collector 截图采集

- **断言**：`capture(device_id)` 内部调 `ADBClient.screenshot(device_id=device_id)`，返回 PNG bytes。
- **断言**：`to_file_url(png_bytes, path)` 写入磁盘，返回 `file:///abs/path/to/file.png` 形式 URL。
- **断言**：`to_data_url(png_bytes)` 返回 `data:image/png;base64,<base64>` 形式（BF003 视觉决策消费格式）。
- **断言**：返回的 bytes 长度 > 0（空 PNG 视为采集失败，抛 `ScreenshotError`）。

### AC-5：reproduce_runner 确定性脚本执行

- **断言**：`ReproduceRunner(client, device_id).run(steps)` 输入 `list[dict]`（每条 `{action, params, expected_signal}`），按顺序执行，返回 `list[ReproStep]`（内存对象，未持久化）。
- **断言**：每个 step 的 `action` 映射到 `adb_tools` 函数：`tap/swipe/input/press/screenshot/wait`（`wait` = `time.sleep`，无 ADB 调用）。
- **断言**：返回的 ReproStep 字段填充：`step_no`（从 1 递增）/ `action` / `target_coords`（tap/swipe 时）/ `target_text`（input 时）/ `expected_signal`（透传输入）/ `screenshot_ref`（每步采集，格式由配置决定 file_url 或 data_url）/ `actual_signal`（logcat 抓取结果，见 AC-6）。
- **断言**：确定性——同一输入多次执行，ReproStep 序列的 `step_no / action / target_coords / target_text / expected_signal` 字段完全一致（`screenshot_ref / actual_signal` 因实时采集可能不同，不断言）。
- **断言**：单 step 执行抛 `ADBError` 时，该 step 的 `actual_signal` 记录 `{error: str(exc), signal_type: 'execution_failure'}`，按配置决定继续（`on_error='continue'`）或中止（`on_error='abort'`，默认 abort）。
- **断言**：`id / trajectory_id` 字段不在此填充（由持久化层/Orchestrator 填），runner 只产出业务字段。

### AC-6：信号采集（最小 logcat）

- **断言**：`_capture_logcat_snapshot(client, device_id)` 调 `adb logcat -d`（一次性 dump，非流式），返回近期 logcat 文本。
- **断言**：`_match_signal(logcat_text, expected_signal)` 按 `expected_signal['pattern']`（正则或关键字）匹配 logcat，命中返回 `{matched: True, signal_type: 'logcat', snippet: '...'}`，未命中返回 `{matched: False, signal_type: 'logcat'}`。
- **断言**：`expected_signal` 为 None 时，`actual_signal = {matched: None, reason: 'no_expected_signal'}`（不断言信号，仅记录采集动作发生）。
- **断言**：logcat 抓取本身失败（ADBError）时，`actual_signal = {matched: None, error: str(exc), signal_type: 'logcat_capture_failure'}`，不中断 runner（runner 的中断由 step 执行错误决定，见 AC-5）。

### AC-7：启动失败转设施缺口

- **断言**：emulator 进程启动失败 → 抛 `EmulatorStartError`，同时调 `GapStore.create({id: <uuid>, gap_type: 'facility', description: 'emulator start failed: ...', linked_bug_ids: [], source_bug_id: None})`。
- **断言**：boot 超时（`wait_boot_complete` 抛 `EmulatorBootTimeoutError`）→ 同样转设施缺口 + 抛异常。
- **断言**：创建的 CapabilityGap `status == 'identified'`（GapStore.create 强制覆盖，见 BF008 实现）。
- **断言**：GapStore 调用失败（DB 异常）时，不掩盖 emulator 原始异常——先记录日志（`logging.warning`），再抛 `EmulatorStartError`（设施缺口创建失败不应阻塞降级路径，Orchestrator 仍能看到 emulator 异常）。
- **断言**：`linked_bug_ids` 为空列表（启动失败时尚未关联具体 bug；后续 BB010 缺口诊断器可 `link_bug` 关联）。

## 实现要点

### Q1：adb_tools 是 class 还是函数模块？

**决策：函数模块（thin wrapper）**。

理由：
- INF05 `ADBClient` 已是 class，再包一层 class 是无意义嵌套。
- 函数模块天然支持 BB003 探测模式（agent tool-calling）：BB003 可直接把 `adb_tools.tap` 等函数注册为 tool，无需实例化。
- 测试 mock 简单（monkeypatch 模块函数即可）。

签名约定（`client` 为首参，由调用方注入）：
```python
def tap(client: ADBClient, x: int, y: int, *, device_id: str | None = None) -> ADBResult: ...
def swipe(client, x1, y1, x2, y2, duration_ms=300, *, device_id=None) -> ADBResult: ...
def input_text(client, text, *, device_id=None) -> ADBResult: ...
def screenshot(client, *, device_id=None) -> ADBResult: ...
def install_apk(client, apk_path, *, device_id=None) -> ADBResult: ...
def press_key(client, keycode, *, device_id=None) -> ADBResult: ...
```

每个函数体仅一行：`return client.<method>(...)`，透传 INF05 结果与异常。

### Q2：emulator_pool 启动方式

`subprocess.Popen([emulator_bin, "-avd", avd_name, "-no-window", "-no-audio", "-no-snapshot"], stdout=DEVNULL, stderr=DEVNULL)`，非阻塞。随后轮询 `adb devices` 拿 device_id，再轮询 `sys.boot_completed`。

### Q3：reproduce_runner 是否持久化 ReproStep？

**决策：不持久化，返回 `list[ReproStep]` 内存对象**。调用方（Orchestrator）决定何时写 DB（解耦；支持测试不碰 DB）。

### Q4：信号采集依赖 BF004？

**决策：不依赖**。BF004 `logcat_listener.py` 当前为空。reproduce_runner 自带 `_capture_logcat_snapshot`（`adb logcat -d` 一次性 dump）+ `_match_signal`（正则/关键字匹配）。接口预留 `signal_collector` 可注入参数，BF004 实现后可注入替代最小实现。

### Q5：启动失败转设施缺口的 GapStore 调用

```python
# emulator_pool.py
def start(self) -> str:
    try:
        proc = subprocess.Popen([...])
        device_id = self._wait_for_device(timeout=30)
        self._wait_boot_complete(device_id, timeout=settings.EMULATOR_BOOT_TIMEOUT)
        return device_id
    except (FileNotFoundError, subprocess.CalledProcessError, EmulatorBootTimeoutError) as e:
        self._create_facility_gap(str(e))  # best-effort，失败仅 warning
        raise EmulatorStartError(...) from e

def _create_facility_gap(self, reason: str) -> None:
    try:
        self._gap_store.create({
            "id": str(uuid4()),
            "gap_type": "facility",
            "description": f"emulator start failed: {reason}",
            "linked_bug_ids": [],
        })
    except Exception as gap_exc:
        logging.warning("GapStore.create failed: %s", gap_exc)
```

### Q6：config 新增字段

- `EMULATOR_BOOT_TIMEOUT: int = 120`（emulator boot 完成超时，env `EMULATOR_BOOT_TIMEOUT`）
- `EMULATOR_BIN: str = ""`（emulator 二进制路径，空走解析：env → SDK 固定路径 → which）
- `SCREENSHOT_FORMAT: str = "data_url"`（`data_url` / `file_url`，控制 screenshot_collector 产出形态）

### Q7：reproduce_runner 的 action 映射

| playbook action | adb_tools 函数 | ReproStep.action | ReproStep 字段填充 |
|----------------|---------------|------------------|-------------------|
| `tap` | `tap(client, x, y)` | `"tap"` | target_coords={x, y} |
| `swipe` | `swipe(client, x1, y1, x2, y2, duration_ms)` | `"swipe"` | target_coords={x1,y1,x2,y2,duration_ms} |
| `input` | `input_text(client, text)` | `"input"` | target_text=text |
| `press` / `back` | `press_key(client, keycode)`（back → keycode="4"） | `"press"` / `"back"` | target_text=keycode |
| `screenshot` | `screenshot(client)` | `"screenshot"` | （仅采集，无动作参数） |
| `wait` | `time.sleep(duration)` | `"wait"` | target_coords={duration_ms} |
