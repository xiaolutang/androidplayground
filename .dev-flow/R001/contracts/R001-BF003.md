## 任务边界

### 做什么（IN scope）

1. **新建 `agent/vision/vision_decision_engine.py`**（当前空文件，待实现）：视觉决策引擎——输入截图（+ 可选锚点对照）→ 调 LLMGateway → 输出下一个 ADB `tool_call` + 置信度 + reasoning。供 BB003 探测/诱发模式（agent loop）消费，复现模式不调用本模块。

2. **决策接口（BF003.1）**：`VisionDecisionEngine.decide(screenshot_url, *, task_desc, anchor_context=None) -> VisionDecision`，返回结构化决策（dataclass，见 Q1）。锚点上下文（来自 BF007 `AnchorLibrary.match_by_visual_features`）可选传入，决定走「锚点对照」还是「纯 LLM」路径（D11）。

3. **LLMGateway 调用（D2）**：固定走 `prompt_type="vision_decision"`，经 INF04 自动路由到 vision 通道（GLM-5V-Turbo）。传入 `image_url=screenshot_url`，INF04 内部升级为多模态 content（text + image_url）。messages 由本模块的 prompt 模板构造（见 Q2）。

4. **锚点对照双模式（D11）**：
   - **有锚点**（`anchor_context` 非空）→ prompt 中嵌入锚点对照描述（page_id + text_expectation + similarity），辅助 LLM 决策；置信度结合 LLM 返回 + 锚点 similarity。
   - **空锚点**（`anchor_context` 为 None / `[]`）→ 纯 LLM 模式（D11 降级），prompt 不含对照段；`used_anchor=False`，置信度仅来自 LLM 自评。

5. **LLM 失败降级不崩**：捕获 INF04 `LLMError`（超时/超限/解析失败耗尽 / FakeLLM 队列空）→ 返回 fallback `VisionDecision`（见 Q4），不抛异常给调用方（BB003 agent loop 继续可运行，由 BB003 自行决定是否中止 loop）。

6. **LLM 响应解析**：期望 GLM-5V-Turbo 返回 JSON 结构化输出（见 Q3），解析 `action / params / confidence / reasoning`。解析失败（JSON 不合法 / 字段缺失 / action 不在白名单）→ 走 fallback 决策（不重试，重试由 INF04 内部负责）。

7. **tool_call 格式与 BF002 adb_tools 对齐**：`action ∈ {tap, swipe, input, press, back, screenshot, wait}`，`params` 字段与 BF002 `adb_tools` 函数签名对齐（见 Q5 映射表）。action 白名单校验在解析层做，非法 action 触发 fallback。

8. **单元测试 + 集成测试**：
   - 单元测试全 mock（`FakeLLMGateway` + AnchorLibrary mock），覆盖：正常决策 / 锚点对照模式 / 空锚点纯 LLM / LLM 失败降级 / JSON 解析失败 / 非法 action / confidence 计算。
   - 集成测试放 `tests/integration_bf003/`，真实调 New API（GLM-5V-Turbo），`@pytest.mark.skipif` 无 `NEW_API_API_KEY` 守护，不进主 CI。

### 不做什么（OUT of scope）

- **不实现 ADB tool 执行**（BF002 负责）：本模块只产出 `VisionDecision`（决策意图），不调 `adb_tools.tap(...)` 等执行函数。执行由 BB003 agent loop 负责。
- **不实现锚点数据录入**（D11 公司后激活）：本模块只消费 `AnchorLibrary.match_by_visual_features` 返回的对照结果，不写入锚点。数据冷启动为空时自动走纯 LLM（D11）。
- **不实现 agent loop / LangGraph 编排**（BB003 负责）：本模块是 BB003 探测/诱发模式的一个工具（看截图→出决策），不维护 loop 状态 / 步数预算（D7）/ 信号循环判断。
- **不实现截图采集**（BF002 `screenshot_collector` 负责）：本模块输入是 `screenshot_url`（file_url 或 data_url，由 BF002 产出），不做 ADB screencap。
- **不实现 embedding / visual_features 生成**：锚点的 `visual_features` 向量由录入时生成（公司后激活），本模块只接收 `match_by_visual_features` 返回的 similarity，不做向量化。
- **不做 LLM 重试**：重试由 INF04 `NewAPILLMGateway` 内部负责（仅解析失败重试 `FIX_RETRY_MAX` 次，耗尽抛 `LLMError`）。本模块捕获 `LLMError` 即走 fallback，不二次重试。
- **不耦合 Orchestrator / BugReport 状态机**：本模块无状态，每次 `decide()` 独立调用，trajectory / step 记录由 BB003 / Orchestrator 负责。
- **不做 prompt 版本管理 / A/B 实验**：MVP 单一 prompt 模板，后续优化在 BB013 反思阶段迭代。

### AC-2：LLMGateway 调用路由（D2）

- **断言**：`decide()` 内部调 `llm_gateway.complete(prompt_type="vision_decision", messages=..., image_url=screenshot_url, ...)`，`prompt_type` 固定为 `"vision_decision"`（INF04 路由到 GLM-5V-Turbo）。
- **断言**：`image_url` 透传给 `complete`（INF04 内部升级为多模态 content）。
- **断言**：`messages` 含 system + user 两条（system 为角色定义，user 含 task_desc + 可选锚点对照描述，见 Q2）。

### AC-3：锚点对照双模式（D11）

- **断言**：`anchor_context` 非空时，user message 中含锚点对照段（page_id / text_expectation / similarity），`used_anchor=True`。
- **断言**：`anchor_context` 为 None 或 `[]` 时，user message 不含对照段，`used_anchor=False`（D11 纯 LLM 降级）。
- **断言**：`anchor_library.is_empty()` 为 True 时，即使调用方未显式传 None，本模块也不主动查锚点（调用方负责决定是否查；本模块只消费传入的 `anchor_context`）。

### AC-4：空锚点降级（D11）

- **断言**：`anchor_context=None` → `used_anchor=False`，`degraded=False`（纯 LLM 是 D11 设计内的正常路径，不是 degraded；degraded 仅指 LLM 失败降级，见 AC-5）。
- **断言**：纯 LLM 模式下 confidence 仅来自 LLM 自评（解析 LLM 返回的 confidence 字段），不叠加锚点 similarity。

### AC-5：LLM 失败降级不崩

- **断言**：`llm_gateway.complete` 抛 `LLMError`（INF04 超时/超限/解析耗尽）→ `decide()` 不抛异常，返回 fallback `VisionDecision`。
- **断言**：fallback 决策固定为 `action="wait"`，`params={"duration_ms": 1000}`，`confidence=0.0`，`reasoning="LLM failed, fallback to wait"`，`used_anchor=False`，`degraded=True`。
- **断言**：fallback 路径记录 `logging.warning("VisionDecision LLM failed: %s", exc)`（便于 BB003 / Orchestrator 监控降级频率）。
- **断言**：连续失败多次不累积状态（无状态模块，每次 decide 独立）。

### AC-6：tool_call 格式与 BF002 adb_tools 对齐

- **断言**：`action` ∈ 白名单 `{tap, swipe, input, press, back, screenshot, wait}`，非法值（如 `"click"`、`"scroll"`）触发 fallback（AC-5 风格，但 `degraded=True` 且 reasoning 标注 "invalid action"）。
- **断言**：`params` 字段与 action 对齐（见 Q5 映射表）：`tap` → `{x, y}`；`swipe` → `{x1, y1, x2, y2, duration_ms}`；`input` → `{text}`；`press` → `{keycode}`；`back` → `{}`；`screenshot` → `{}`；`wait` → `{duration_ms}`。
- **断言**：`params` 字段类型合规（x/y 为 int，text 为 str，duration_ms 为 int）；类型不合规触发 fallback。

### AC-7：置信度计算

- **断言**：纯 LLM 模式（`used_anchor=False`）：`confidence = LLM 返回的 confidence 字段`（LLM 自评，0.0-1.0）。
- **断言**：锚点对照模式（`used_anchor=True`）：`confidence = 0.6 * LLM_confidence + 0.4 * top_similarity`（加权融合，LLM 主导 + 锚点辅证）。
- **断言**：LLM 返回的 confidence 缺失 / 越界（<0 或 >1）→ clamp 到 [0.0, 1.0]（缺失取 0.5 默认值）。
- **断言**：fallback 路径 `confidence=0.0`（AC-5）。

## 实现要点

### Q1：VisionDecision 数据结构？

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class VisionDecision:
    """视觉决策引擎输出（BF003）。

    Attributes:
        action: ADB tool 动作，∈ {tap, swipe, input, press, back, screenshot, wait}。
        params: 动作参数，与 BF002 adb_tools 函数签名对齐（见 Q5）。
        confidence: 决策置信度 [0.0, 1.0]。纯 LLM 模式取 LLM 自评；
            锚点对照模式 = 0.6*LLM + 0.4*top_similarity。
        reasoning: LLM 给出的决策理由（fallback 时为降级说明）。
        used_anchor: 是否使用了锚点对照（D11 纯 LLM 时为 False）。
        degraded: 是否为降级决策（LLM 失败 / 解析失败 / 非法 action 时为 True）。
    """
    action: str
    params: dict
    confidence: float
    reasoning: str
    used_anchor: bool
    degraded: bool
```

### Q2：prompt 模板？

```python
SYSTEM_PROMPT = (
    "你是移动端测试专家，正在通过 ADB 操控 Android 模拟器复现 bug。"
    "你会收到一张当前屏幕截图和任务描述，需要决策下一个 ADB 操作。\n"
    "只输出 JSON，格式："
    '{"action": "<tap|swipe|input|press|back|screenshot|wait>", '
    '"params": {...}, "confidence": <0-1>, "reasoning": "<简短理由>"}\n'
    "params 约定：tap={x,y}; swipe={x1,y1,x2,y2,duration_ms}; "
    "input={text}; press={keycode}; back={}; screenshot={}; wait={duration_ms}。"
)

# user message 构造（锚点对照段可选）
def _build_user_message(task_desc: str, anchor_context: list | None) -> str:
    msg = f"任务：{task_desc}\n\n请决策下一步操作。"
    if anchor_context:
        msg += "\n\n[锚点对照] 检测到当前页面与以下锚点相似：\n"
        for anchor, sim in anchor_context[:3]:  # top 3
            msg += (
                f"- page_id={anchor.page_id}, "
                f"text_expectation={anchor.text_expectation}, "
                f"similarity={sim:.2f}\n"
            )
    return msg
```

注：`image_url` 由 INF04 内部拼到 user message 的 content list（text + image_url），本模块只传 text 部分（task_desc + 可选对照）。

### Q3：LLM 返回解析？

```python
import json

def _parse_llm_response(content: str) -> dict | None:
    """解析 LLM 返回的 JSON。失败返回 None（调用方走 fallback）。"""
    try:
        data = json.loads(content.strip())
    except (json.JSONDecodeError, AttributeError):
        return None
    # 字段校验
    required = {"action", "params"}
    if not all(k in data for k in required):
        return None
    if data["action"] not in _VALID_ACTIONS:  # 见 Q5
        return None
    if not isinstance(data["params"], dict):
        return None
    return data
```

### Q4：fallback 决策？

固定值（避免 fallback 本身再出错）：
```python
def _fallback_decision(reason: str) -> VisionDecision:
    return VisionDecision(
        action="wait",
        params={"duration_ms": 1000},
        confidence=0.0,
        reasoning=f"fallback: {reason}",
        used_anchor=False,
        degraded=True,
    )
```

调用时机：`LLMError` 捕获 / JSON 解析返回 None / action 非法 / params 类型不合规。reason 标注具体原因（"LLM failed" / "parse failed" / "invalid action" / "invalid params type"）。

### Q5：tool_call action 映射（与 BF002 adb_tools 对齐）

| action | BF002 adb_tools 函数 | params 字段 | params 类型约束 |
|--------|---------------------|-------------|----------------|
| `tap` | `tap(client, x, y)` | `{x: int, y: int}` | x/y ∈ int |
| `swipe` | `swipe(client, x1, y1, x2, y2, duration_ms=300)` | `{x1, y1, x2, y2, duration_ms}` | 全 int，duration_ms 可缺省（默认 300） |
| `input` | `input_text(client, text)` | `{text: str}` | text ∈ str |
| `press` | `press_key(client, keycode)` | `{keycode: str}` | keycode ∈ str |
| `back` | `press_key(client, "4")` | `{}` | 空 dict（back 是 press keycode=4 的语法糖） |
| `screenshot` | `screenshot(client)` | `{}` | 空 dict |
| `wait` | `time.sleep(duration)`（BF002 reproduce_runner 内） | `{duration_ms: int}` | duration_ms ∈ int |

白名单：`_VALID_ACTIONS = {"tap", "swipe", "input", "press", "back", "screenshot", "wait"}`

### Q6：decide() 主流程伪代码

```python
async def decide(
    self,
    screenshot_url: str,
    *,
    task_desc: str,
    anchor_context: list[tuple[Anchor, float]] | None = None,
) -> VisionDecision:
    used_anchor = bool(anchor_context)
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": _build_user_message(task_desc, anchor_context)},
    ]
    try:
        resp = await self._llm.complete(
            prompt_type="vision_decision",
            messages=messages,
            image_url=screenshot_url,
        )
    except LLMError as exc:
        logger.warning("VisionDecision LLM failed: %s", exc)
        return _fallback_decision("LLM failed")

    parsed = _parse_llm_response(resp.content)
    if parsed is None:
        return _fallback_decision("parse failed")

    # params 类型校验（略，按 Q5 表逐 action 校验）
    if not _validate_params(parsed["action"], parsed["params"]):
        return _fallback_decision("invalid params type")

    llm_conf = _clamp_confidence(parsed.get("confidence", 0.5))
    confidence = (
        0.6 * llm_conf + 0.4 * anchor_context[0][1]
        if used_anchor and anchor_context
        else llm_conf
    )

    return VisionDecision(
        action=parsed["action"],
        params=parsed["params"],
        confidence=confidence,
        reasoning=parsed.get("reasoning", ""),
        used_anchor=used_anchor,
        degraded=False,
    )
```
