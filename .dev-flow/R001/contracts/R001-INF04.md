## 任务边界

### 做什么（IN scope）
1. 新建 `agent/infra/llm_gateway.py`，实现 `LLMGateway` Protocol + `NewAPILLMGateway` 实现。
2. 业务 prompt_type → model 路由层（4 类业务 prompt 映射到 text/vision 通道）：
   - `vision_decision` → vision model（config.LLM_VISION_MODEL = GLM-5V-Turbo）
   - `symptom_classify` / `fix_patch` / `reflection` → text model（config.LLM_TEXT_MODEL = glm-5.1）
3. 基于 `openai.AsyncOpenAI(base_url=LLM_BASE_URL, api_key=...)` 的 OpenAI 兼容协议封装，走 `chat.completions`。
4. 多模态抽象：`vision_decision` 链路支持 `image_url` 输入参数（messages 构造包含 image_url 类型 content）。
5. 解析失败/非法 JSON 重试机制：最多 `FIX_RETRY_MAX`（默认 3）次，耗尽后抛 `LLMError`。
6. 超时/超限/异常统一抛 `LLMError`（供调用方降级），不崩溃。
7. `dotenv` 加载：新增 `python-dotenv` 依赖；在 config.py 或 llm_gateway.py 加载点读 `agent/.env`（NEW_API_BASE_URL / NEW_API_API_KEY）。
8. `LLMResponse` 数据结构（content / raw / model / usage 等字段）。
9. 单元测试（FakeLLMGateway mock）：路由分发 / 非法 JSON 重试 / 超时降级 / 4 个 scenarios。
10. 集成测试：文本链路真实调用 glm-5.1（从 .env 读凭据）；视觉链路 skip（GLM-5V-Turbo 不可用）。

### 不做什么（OUT of scope）
- **不实现具体业务逻辑**：症状分类（BB002）、修复 patch（BB007）、反思（BB013）的业务 prompt 模板由各自 BB 任务负责；INF04 只提供 gateway 通道。
- **不改 config.py 的 LLM_VISION_MODEL**：保持 `GLM-5V-Turbo`（design D2 决策，BF003 阶段再配视觉模型真实集成）。
- **不强制视觉链路真实调用**：GLM-5V-Turbo 不在 New API 可用列表，集成测试用 `pytest.mark.skip` 标记，BF003 再补真实验证。
- **不实现流式（streaming）**：MVP 用非流式 `chat.completions.create`。
- **不实现 token 计数/预算控制**：token 预算由 Orchestrator（BB004/INF02 参数）负责，gateway 只透传 usage。

## 验收标准（可测试）

### AC-1：prompt_type → model 路由（D2）
- **断言**：调用 `complete("vision_decision", ...)` 时，底层 `chat.completions` 的 `model` 参数 == `settings.LLM_VISION_MODEL`（GLM-5V-Turbo）。
- **断言**：调用 `complete("symptom_classify", ...)` / `complete("fix_patch", ...)` / `complete("reflection", ...)` 时，`model` 参数 == `settings.LLM_TEXT_MODEL`（glm-5.1）。
- **断言**：传入非法 prompt_type（如 `"unknown"`）→ 抛 `ValueError` 或 `LLMError`（fail-fast，不静默用错 model）。
- **实现要点**：新增业务层映射 `_PROMPT_TYPE_TO_CHANNEL = {"vision_decision": "vision", "symptom_classify": "text", "fix_patch": "text", "reflection": "text"}`，再调 `config.get_llm_model(channel)`。

### AC-2：OpenAI 兼容协议
- **断言**：`NewAPILLMGateway` 初始化时创建 `openai.AsyncOpenAI(base_url=settings.LLM_BASE_URL, api_key=<from env>)` 实例。
- **断言**：`complete()` 内部调用 `client.chat.completions.create(model=..., messages=..., **kw)`。
- **断言**：api_key 从 `NEW_API_API_KEY` 环境变量读取（dotenv 加载后可见）。

### AC-3：重试机制（非法 JSON / 解析失败）
- **断言**：当 LLM 返回内容无法解析为目标格式（如非法 JSON）时，重试调用，重试次数 <= `FIX_RETRY_MAX`（3）。
- **断言**：重试耗尽后抛 `LLMError`（不返回部分结果）。
- **断言**：`FIX_RETRY_MAX=0` 时不重试，首次失败即抛 `LLMError`。

### AC-4：超时/超限降级（不崩溃）
- **断言**：底层 `AsyncOpenAI` 抛超时异常（`asyncio.TimeoutError` / `openai.APITimeoutError`）→ 捕获并抛 `LLMError`。
- **断言**：底层抛 `openai.RateLimitError` / `openai.APIStatusError` → 捕获并抛 `LLMError`。
- **断言**：`LLMError` 包含原始异常信息（`cause` / `__cause__` 可追溯）。

### AC-5：文本链路真实可用（集成测试）

## 实现要点

### 1. 业务 prompt_type → channel 映射层
```python
# llm_gateway.py
_PROMPT_TYPE_TO_CHANNEL: dict[str, str] = {
    "vision_decision": "vision",
    "symptom_classify": "text",
    "fix_patch": "text",
    "reflection": "text",
}

def _route_model(prompt_type: str, settings: Settings) -> str:
    channel = _PROMPT_TYPE_TO_CHANNEL.get(prompt_type)
    if channel is None:
        raise ValueError(f"unsupported prompt_type={prompt_type!r}")
    return get_llm_model(channel, settings)
```

### 2. LLMGateway Protocol + NewAPILLMGateway 实现
```python
class LLMGateway(Protocol):
    async def complete(
        self,
        prompt_type: Literal["vision_decision", "symptom_classify", "fix_patch", "reflection"],
        *,
        messages: list[dict],
        image_url: str | None = None,
        **kwargs,
    ) -> LLMResponse: ...

class NewAPILLMGateway:
    def __init__(self, settings: Settings | None = None):
        self._settings = settings or get_settings()
        self._client = openai.AsyncOpenAI(
            base_url=self._settings.LLM_BASE_URL,
            api_key=os.getenv("NEW_API_API_KEY", ""),
        )

    async def complete(self, prompt_type, *, messages, image_url=None, **kwargs) -> LLMResponse:
        model = _route_model(prompt_type, self._settings)
        # vision_decision 且 image_url 非空 → 构造多模态 messages
        ...
```

### 3. LLMResponse 数据结构
```python
@dataclass(frozen=True)
class LLMResponse:
    content: str
    model: str
    raw: object | None = None  # 原始 completion 对象
    usage: dict | None = None  # token usage（透传，不计数）
```

### 4. LLMError 异常
```python
class LLMError(Exception):
    """LLM 调用异常（超时/超限/解析失败耗尽），供调用方降级。"""
```

### 5. 重试逻辑
- 解析返回内容失败（非法 JSON / 空 content）→ 重试，计数 +1。
- 重试上限 = `settings.FIX_RETRY_MAX`；耗尽抛 `LLMError`。
- 超时/超限/网络异常不重试（直接抛 `LLMError`，避免放大故障）。

### 6. dotenv 加载
- `agent/pyproject.toml` 新增依赖：`"python-dotenv==1.1.0"`。
- `config.py` 顶部（import os 之后）加 `from dotenv import load_dotenv; load_dotenv()`，确保 Settings 读取前 .env 已加载。
