## 任务边界

### 做什么（IN scope）
1. 新建 `agent/infra/adb_client.py`，封装 `subprocess` 调 adb（D3 subprocess 底座）。
2. 暴露六个动作：`tap / swipe / input_text / screenshot / install_apk / press_key`，每个动作返回 `ADBResult` 或抛异常。
3. **adb 二进制解析**（三段式 fallback）：
   - 优先 `os.getenv("ADB_BIN")`
   - 次选 `shutil.which("adb")`
   - 末选固定路径常量（mac 默认 `~/Library/Android/sdk/platform-tools/adb`，Linux 默认 `/usr/bin/adb`，经 `sys.platform` 判定）
   - 三段都找不到 → 抛 `ADBConfigError`（启动期 fail-fast，不等到动作执行）。
4. **本地 vs 网络桥自适应**（D10）：
   - `settings.ADB_HOST` 为空串 `""` → 本地模式，不加 `-H/-P` 参数
   - `settings.ADB_HOST` 非空 → 网络桥模式，加 `-H <host> -P <port>` 参数
   - **config.py 默认值调整**：`ADB_HOST` 默认值从 `"host.docker.internal"` 改为 `""`（本机直跑默认本地，容器跑通过 env 注入 host.docker.internal）
5. **device_id 路由**：每个动作支持可选 `device_id` 参数（多模拟器场景）；非空时加 `-s <device_id>` 前缀。
6. **超时与重试**：
   - 默认动作超时 `ADB_ACTION_TIMEOUT=10` 秒（config 新增字段，env 可覆盖）
   - 重试上限 `ADB_RETRY_MAX=2`（独立于 `FIX_RETRY_MAX`，config 新增字段）
   - 重试退避：立即重试（无 sleep），仅对 `ADBTimeoutError` 与非零退出码重试；`ADBConnectionError` 不重试（adb server 不可达重试无意义，直接上抛）。
7. **异常分类**：三类异常 + 一个配置异常
   - `ADBError`（基类）
   - `ADBConnectionError`（adb server 不可达 / 设备 offline / `adb devices` 返回空或 device 状态非 device）
   - `ADBCommandError`（命令执行失败，非零退出码且非连接类）
   - `ADBTimeoutError`（`subprocess.TimeoutExpired` 捕获后包装）
   - `ADBConfigError`（adb 二进制找不到 / 配置非法，启动期抛）
8. **screenshot 文件流转**：`screenshot()` 调 `adb exec-out screencap -p > bytes`（用 `subprocess.run(..., capture_output=True)` 拿 stdout 二进制，避免临时文件 + `adb pull` 两步）。
9. **install_apk**：调 `adb install -r <apk_path>`，apk_path 不存在抛 `ADBCommandError`。
10. **单元测试**（全 mock subprocess.run）：6 actions + 重试 + 异常分类 + 网络桥参数构造 + 本地/网络桥自适应 + device_id 路由。
11. **集成测试**（skipif 无设备守护）：`@pytest.mark.skipif` 当 `adb devices` 为空或 adb 不可达时 skip。

### 不做什么（OUT of scope）
- **不实现 BF002 工具层语义**（复现脚本编排、ReproStep 采集、双模式分发）：INF05 只提供原子动作底座，BF002 在其上封装工具接口与编排。INF05 的 6 个动作签名必须与 BF002.1 期望一致（见 AC-7），但业务语义留给 BF002。
- **不管理模拟器生命周期**（启停/分配）：BF002 `emulator_pool.py` 负责。
- **不做 `adb connect/disconnect` 主动连远程设备**：D10 网络桥是「连宿主 adb server」，不是「adb connect 远程设备」。设备发现走 `adb devices -l`（在 `wait_for_device` 辅助方法中）。
- **不实现 logcat 长连接流式监听**：BF004 `logcat_listener.py` 负责；INF05 只做一次性 subprocess 调用。
- **不改 config.py 已有字段名**：`ADB_HOST` / `ADB_PORT` 字段名保留，只调默认值（见 AC-2）；新增 `ADB_BIN` / `ADB_ACTION_TIMEOUT` / `ADB_RETRY_MAX` 字段。
- **不强依赖模拟器**：集成测试用 `skipif` 守护，无设备时 skip 不 fail。
- **不实现异步接口**：MVP 用同步 `subprocess.run`（adb 动作是阻塞 I/O，复现脚本顺序执行；异步化留给后续如果 BF002 LangGraph loop 需要）。

## 验收标准（可测试）

### AC-1：adb 二进制三段式解析
- **断言**：`os.getenv("ADB_BIN")` 非空时，`_resolve_adb_bin()` 返回该值（测试 monkeypatch `ADB_BIN=/custom/adb`）。
- **断言**：`ADB_BIN` 未设 + `shutil.which("adb")` 返回 `/usr/local/bin/adb` 时，`_resolve_adb_bin()` 返回该值（monkeypatch `shutil.which`）。
- **断言**：`ADB_BIN` 未设 + `which` 返回 None + 平台为 darwin 时，返回 `~/Library/Android/sdk/platform-tools/adb`。
- **断言**：三段都找不到（`ADB_BIN` 空 + which None + 固定路径不存在）→ 抛 `ADBConfigError`，错误信息含已尝试的路径列表。
- **断言**：解析结果在 `ADBClient.__init__` 时缓存（不每次动作都解析）。

### AC-2：本地 vs 网络桥参数构造（D10）
- **断言**：`settings.ADB_HOST=""` 时，`_build_base_args()` 返回 `["/path/to/adb"]`（无 `-H/-P`）。
- **断言**：`settings.ADB_HOST="host.docker.internal"` + `ADB_PORT=5037` 时，`_build_base_args()` 返回 `["/path/to/adb", "-H", "host.docker.internal", "-P", "5037"]`。
- **断言**：`config.py` 的 `ADB_HOST` 默认值改为 `""`（本地直跑默认）；`ADB_PORT` 保持 5037（网络桥启用时生效）。
- **断言**：env `ADB_HOST=host.docker.internal` 覆盖后，`get_settings().ADB_HOST == "host.docker.internal"`（容器跑通过 env 注入网络桥）。

### AC-3：六个动作 subprocess 调用契约
- **断言 tap(x, y)**：`subprocess.run` 收到 args = `base + [-s <dev>] + ["shell", "input", "tap", "<x>", "<y>"]`（device_id 省略时无 `-s`）。
- **断言 swipe(x1,y1,x2,y2,duration_ms)**：args 含 `["shell", "input", "swipe", x1, y1, x2, y2, str(duration_ms)]`。
- **断言 input_text(text)**：args 含 `["shell", "input", "text", text]`。
- **断言 screenshot()**：args = `base + ["exec-out", "screencap", "-p"]`，返回 `ADBResult.stdout` 为 PNG 二进制（非空 bytes）。
- **断言 install_apk(apk_path)**：args 含 `["install", "-r", apk_path]`；apk_path 不存在抛 `ADBCommandError`。
- **断言 press_key(keycode)**：args 含 `["shell", "input", "keyevent", keycode]`。
- **断言**：每个动作返回 `ADBResult(returncode=0, stdout=..., stderr=...)` dataclass。

### AC-4：device_id 路由
- **断言**：`tap(100, 200, device_id="emulator-5554")` 时 args 含 `-s emulator-5554`（紧跟 base args 之后、子命令之前）。
- **断言**：`device_id=None`（默认）时 args 无 `-s` 段。

### AC-5：超时与重试
- **断言**：动作执行时间超过 `ADB_ACTION_TIMEOUT`（默认 10s）→ 抛 `ADBTimeoutError`。
- **断言**：`ADBTimeoutError` 触发重试，重试次数 ≤ `ADB_RETRY_MAX`（默认 2）；耗尽后抛最后一次的 `ADBTimeoutError`。
- **断言**：非零退出码（如 `adb shell input tap` 在设备上失败）→ 抛 `ADBCommandError`，触发重试；耗尽抛 `ADBCommandError`。
- **断言**：`ADBConnectionError`（adb server 不可达）→ 不重试，直接上抛（避免无意义重试放大故障）。
- **断言**：重试无 sleep（立即重试，MVP 简化）。

### AC-6：异常分类
- **断言**：`subprocess.TimeoutExpired` 被捕获包装为 `ADBTimeoutError`（保留 `__cause__`）。
- **断言**：`subprocess.run` 返回 returncode != 0 且 stderr 含 "device offline" / "device not found" / "cannot connect to daemon" → `ADBConnectionError`。
- **断言**：returncode != 0 且 stderr 不含连接类关键词 → `ADBCommandError`。
- **断言**：所有异常继承 `ADBError` 基类（调用方可 `except ADBError` 统一捕获）。
- **断言**：异常 message 含原始 args + stdout + stderr（便于排查）。

### AC-7：BF002 工具层接口对齐
- **断言**：6 个动作的方法名与签名与 BF002.1 adb_tools 期望一致：
  ```python

  ```
- **断言**：`ADBClient` 可直接被 BF002 包装为工具接口（无需 BF002 重新实现 subprocess 调用）。

### 2. 二进制解析（三段式）
```python
def _resolve_adb_bin() -> str:
    # 1. env ADB_BIN
    env_bin = os.getenv("ADB_BIN")
    if env_bin and Path(env_bin).exists():
        return env_bin
    # 2. shutil.which
    which_bin = shutil.which("adb")
    if which_bin:
        return which_bin
    # 3. 固定路径（按平台）
    fixed = _platform_default_adb()
    if fixed and Path(fixed).exists():
        return fixed
    raise ADBConfigError(f"adb binary not found: tried env ADB_BIN={env_bin!r}, PATH(which)={which_bin!r}, fixed={fixed!r}")
```

### 3. 异常分类（stderr 关键词）
```python
_CONNECTION_KEYWORDS = ("device offline", "device not found", "cannot connect to daemon", "failed to connect")

def _classify_error(result: subprocess.CompletedProcess) -> ADBError:
    stderr_lower = (result.stderr or "").lower()
    if any(kw in stderr_lower for kw in _CONNECTION_KEYWORDS):
        return ADBConnectionError(...)
    return ADBCommandError(...)
```

## 关键决策（协商结论）

| 问题 | 决策 | 理由 |
|------|------|------|
| a. adb 二进制路径 | 方案 A：env `ADB_BIN` → `shutil.which` → 平台固定路径，三段式 fail-fast | 本机 adb 在 SDK 固定路径不在 PATH；容器跑时 Dockerfile 装 platform-tools 进 PATH；三段式覆盖两种部署形态 |
| b. 本地 vs 网络桥 | `ADB_HOST=""` = 本地（不加 -H/-P）；非空 = 网络桥；config 默认值改 `""` | 本机直跑是更安全默认；容器跑通过 env 注入 `host.docker.internal`；避免本机直跑时连不上 host.docker.internal 启动即崩 |
| c. screenshot | `adb exec-out screencap -p`，stdout 直接拿 PNG bytes | 避免临时文件 + adb pull 两步；exec-out 不会被 \r\n 污染（shell 才会） |
| d. 超时/重试 | 动作超时 10s / 重试 2 次 / 立即重试 / 连接错不重试 | 独立于 FIX_RETRY_MAX（语义不同：FIX_RETRY_MAX 是修复策略重试，ADB_RETRY_MAX 是 IO 重试）；连接错重试无意义 |
| e. 异常分类 | 4 类（ADBError 基类 + Connection/Command/Timeout + ConfigError 启动期） | stderr 关键词匹配连接类；调用方可统一 catch ADBError 或精细处理 |
| f. 测试策略 | 单测全 mock（6 actions + 重试 + 异常）+ 集成 skipif 守护 | 单测保逻辑正确性；集成不强依赖模拟器保 CI 稳定 |
