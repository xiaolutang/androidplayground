## 1. 目标

建立三类基线报告方法，MVP 验收 = 方法可执行 + 基线报告产出（非数值达标）。

## 2. AC（验收标准）

### AC-1：LLM patch 命中率报告
- 每 prompt_type ≥20 标注样本（fix_patch/diagnose/classify/reflection）
- 真实 LLM 跑（LLMGateway→glm-5.1）
- 断言：
  - Schema 合规率 ≥95%（输出格式符合 FixPatch/ReflectionResult 等 dataclass）
  - 关键字段命中率 ≥80%（root_cause/patch_content/negative_knowledge 等核心字段非空且语义正确）
- 产出：`tests/golden/llm_quality/report.md`（命中率表 + 样本明细）
- MVP 降级：样本数不足 20 时，用已有样本出报告（标注 N 值），方法可执行即 pass

### AC-2：置信度校准报告
- 用 BB006 ConfidenceScorer 输出 + 真实 outcome（修复成功/失败）
- reliability diagram（分桶：0-0.2/0.2-0.4/0.4-0.6/0.6-0.8/0.8-1.0，每桶预测概率 vs 实际频率）
- Brier score（均方误差，越低越好）
- 产出：`tests/golden/confidence/calibration_report.md`
- MVP 降级：真实 outcome 样本不足时，用合成数据演示方法（标注"合成"），方法可执行即 pass

### AC-3：视觉决策 golden 报告
- 人工造截图样本（≥10 张：白屏/黑屏/加载中/正常/异常混合）
- BF003 VisualDecisionEngine 检测结果 vs 人工标注
- 冷启动 ≥50%（D11 锚点库空时，纯像素方差检测的准确率）
- 产出：`tests/golden/vision/report.md`（混淆矩阵 + 准确率）
- MVP 降级：样本不足 50 张时，用已有样本出报告（标注 N 值）

### AC-4：报告产出可执行
- 三类报告都有对应的生成脚本（`tests/golden/run_*.py`）
- 脚本可独立运行（`python3 tests/golden/run_llm_quality.py`）
- 输出 markdown 报告到指定路径

### AC-5：不进主 CI
- golden 测试标记 `@pytest.mark.golden`（需 `--run-golden` 显式触发）
- 不在默认 `pytest` 运行范围内
- 不阻塞主 CI

## 3. 实现约束

### 文件清单
- `tests/golden/llm_quality/samples/`（标注样本 JSON）
- `tests/golden/llm_quality/run_llm_quality.py`（LLM 命中率报告脚本）
- `tests/golden/confidence/run_calibration.py`（置信度校准脚本）
- `tests/golden/vision/samples/`（截图样本）
- `tests/golden/vision/run_vision.py`（视觉决策报告脚本）
- `tests/golden/conftest.py`（golden marker 注册）
- `tests/golden/__init__.py`

### 关键实现决策
1. **MVP 验收标准**：方法可执行 + 报告产出（非数值达标），冷启动阶段数值仅供参考
2. **样本准备**：LLM 用合成 bug 场景（crash NPE/blank screen/loading 卡住）；视觉用 PIL 生成纯色/噪声图
3. **真实 LLM 可选**：跑 LLM 报告需要 API key，无 key 时用 mock 演示方法（标注 "mock"）
4. **golden marker**：`pytest.ini` 或 `conftest.py` 注册 `--run-golden` 选项

### 禁止
- golden 测试进默认 CI（会因 LLM 调用/截图依赖拖慢 CI）
- 数值不达标即 fail（MVP 阶段只看方法可执行性）
