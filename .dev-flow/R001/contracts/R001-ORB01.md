## 2. AC（验收标准）

### AC-1：BugReport 14 态状态机迁移合法（100% 合法迁移）
- 定义 `_STATE_TRANSITIONS: dict[BugReportStatus, frozenset[BugReportStatus]]` 迁移矩阵
- 14 态完整：`received`, `assessing`, `degraded`, `reproducing`, `located`, `fixing`, `verified`, `pr_open`, `draft_pr`, `gap_pending`, `wont_reflow`, `concluded`, `reflowed`, `reflected`
- 合法迁移：
  - `received → assessing`
  - `assessing → degraded | reproducing`（ISM 判定信息不足 → degraded；充足 → reproducing）
  - `degraded → received`（缺口补齐回流，路径 A，BB011 事件驱动）
  - `reproducing → located`（根因定位完成）
  - `located → fixing | gap_pending`（有可修复根因 → fixing；需补齐 → gap_pending）
  - `fixing → verified`（三关通过）
  - `fixing → located`（根因错回退，BB004 根因回退）
  - `verified → pr_open | draft_pr`（Tier1 → pr_open；Tier2 → draft_pr）
  - `pr_open → concluded`（人工合并后）
  - `draft_pr → concluded`（人工合并后）
  - `concluded → reflected`（BB013 反思完成）
  - `concluded | reflected → reflowed`（regression-feedback 路径 B，INV-3 唯一 concluded 后迁移）
  - `reflowed → received`（重跑主链）
  - `gap_pending → wont_reflow | received`（超限转人工 / 补齐回流）
- 非法迁移抛 `InvalidStateTransition` 异常
- 测试：构造全部合法迁移 + 至少 5 条非法迁移断言抛异常

### AC-2：LangGraph 节点编排主链
- 节点序列（按主链）：
  1. `normalize`（归一化，BF001 适配器输出）
  2. `assess`（BB001 ISM 评估信息完备度）
  3. `classify`（BB002 症状分类 + BB006 置信度 → Tier 分级）
  4. `select_playbook`（BB003 选择 Playbook）
  5. `diagnose`（BB004 假设树 + BB005 根因定位）
  6. `route_by_tier`（按 Tier 分流）
  7. `fix`（BB007 自动修复，Tier1/Tier2）
  8. `verify`（BB008 回归验证，Tier1/Tier2）
  9. `submit_pr`（BB009 PR 提交）
  10. `diagnose_gap`（BB010 缺口诊断，Tier3/4）
  11. `reflect`（BB013 反思，终态）
- 条件边（conditional edges）实现 Tier 分流：
  - Tier1 → fix → verify → submit_pr(is_draft=false)
  - Tier2 → fix → verify → submit_pr(is_draft=true)
  - Tier3/4 → diagnose_gap → gap_pending
- 测试：mock 全部 BB 服务，验证节点按序执行 + Tier 分流正确

### AC-3：步数预算硬约束（D7）
- `max_steps` 全局硬约束（默认 30，可配）
- 每步递增 `step_used`，超限 → 终止 + 转 BB010 缺口（gap_type=coverage）
- 单假设 `step_budget`（BB004 内部，默认 5）独立于全局 `max_steps`
- 测试：构造步数耗尽场景，断言转 gap_pending + gap_type=coverage

### AC-4：token 预算硬约束（D7）
- `max_tokens` 全局硬约束（默认 100000，可配）
- 每步累加 `token_used`（从 LLMGateway 响应取），超限 → 终止 + 转 BB010 缺口（gap_type=information）
- 测试：构造 token 超限场景，断言转 gap_pending + gap_type=information

### AC-5：人工闸门（INV-2，不自主合并）
- `concluded` 状态只能由人工（外部 API 调用 / webhook）触发，Orchestrator 不自动调用 git merge
- PR 提交后状态停 in `pr_open`/`draft_pr`，等待人工合并信号
- 测试：断言主链执行完后状态 ∈ {pr_open, draft_pr, gap_pending, wont_reflow}，不自动 concluded

### AC-6：事件驱动回流（BB011 解耦）
- Orchestrator 订阅 `bug.reflowed` 事件（EventBus.subscribe）
- 收到事件后迁移状态 `reflowed → received`（路径 A）或保持 `reflowed → received`（路径 B），重跑主链
- `reflow_count` 超限 → `wont_reflow` 转人工（AP-1）
- 测试：mock EventBus 发布 reflowed 事件，断言状态迁移 + 主链重跑触发

### AC-7：BugReport 持久化状态
- 每次状态迁移后更新 `BugReport.status` + `step_used` + `token_used`（持久化）
- 异常时状态不破坏（原子性：迁移失败回滚）
- 测试：构造中途异常，断言状态未半迁移

### AC-8：降级（冷启动优雅）
- 任一 BB 服务不可用（KB 空 / LLM 超时 / 模拟器断）→ 降级到对应缺口（BB010）
- 不抛未捕获异常，记录 reasoning
- 测试：mock BB 服务异常，断言降级到 gap_pending 不崩

### AC-9：AgentState 数据结构
- LangGraph AgentState dataclass（TypedDict 或 dataclass）含：
  - `bug_report_id: str`
  - `status: BugReportStatus`
  - `tier: Optional[int]`
  - `step_used: int`
  - `token_used: int`
  - `hypothesis_ids: list[str]`
  - `root_cause: Optional[dict]`
  - `fix_patch: Optional[FixPatch]`
  - `pr_result: Optional[PRSubmissionResult]`
  - `gap_id: Optional[str]`
  - `errors: list[str]`
- 测试：断言字段集 + 默认值

### AC-10：测试覆盖（无 DB/LLM/模拟器依赖）
- 全部单元测试用 mock，无真实 DB/LLM/模拟器调用
- 至少覆盖：14 态合法迁移 + 5 非法迁移 + Tier1/Tier2/Tier3-4 三条主链路径 + 步数耗尽 + token 超限 + 人工闸门 + 事件回流 + 服务降级
- 预估 ≥ 25 测试

## 3. 实现约束

### 文件清单

### 关键实现决策
1. **LangGraph 状态机（D1）**：使用 `langgraph.graph.StateGraph`，节点函数接收/返回 AgentState
2. **`clarifying` 不是独立状态**：`assessing` + `clarify_requested=true` 子回路（design 4.1 已明确）
3. **步数/token 独立检查**：step_used > max_steps → coverage 缺口；token_used > max_tokens → information 缺口
4. **事件回流解耦**：Orchestrator 订阅 BB011 的 `bug.reflowed` 事件，不反向调用 BB011
5. **concluded 非自动**：INV-2 人工闸门，pr_open/draft_pr 停等人工信号

### 禁止
- 自主调用 git merge（INV-2）
- concluded 自动回退除 reflowed（INV-3）
- 直接调用 BB011（事件驱动解耦，Orchestrator 是订阅方）
