### 实现决策
1. `SymptomType(str, Enum)` 5 值与 `playbook.schema.VALID_SYMPTOM_TYPES`（L43-49）完全对齐；`str, Enum` 便于 JSON 序列化与跨模块字符串比较
2. `_VALID_SYMPTOM_VALUES` frozenset 从枚举派生（`frozenset(s.value for s in SymptomType)`），避免硬编码漂移
3. `ClassificationResult` 使用 `@dataclass(frozen=True)`，字段：symptom_type(str) / confidence(float) / reasoning(str) / degraded(bool) / fallback_used(bool)
4. LLM 主路径：`llm.complete(prompt_type="symptom_classify", messages=...)`，system prompt 限定输出 JSON `{"symptom_type", "confidence", "reasoning"}`
5. JSON 解析 `_parse_llm_json` 三路径容错（与 ISM 风格一致）：```json 围栏 / 裸 JSON / `{...}` 子串提取
6. LLM 失败 / 非法 symptom_type / JSON 解析失败 → 规则兜底（`_rule_fallback`）：关键字映射表从 stacktrace + error_type + raw_report 文本推断，confidence=0.3, degraded=True, fallback_used=True
7. 关键字映射表 `_FALLBACK_KEYWORDS` 顺序敏感（crash > blank > loading > no_response），首个命中即返回；无匹配 → data_error（AC 默认分类）
8. confidence 钳制到 [0.0, 1.0]（`_extract_confidence`）；LLM 成功路径缺 confidence → 默认 0.5
9. bug_report duck typing：`_get_field` 统一访问 ORM 对象（getattr）和 dict（dict.get）；error_type / stacktrace 既可顶层字段，也可嵌在 raw_report dict 内
10. 边界明确：不更新 BugReport.symptom_type（Orchestrator 负责）、不消费 KB 检索结果（BB003 负责）、不持久化（纯计算函数）
