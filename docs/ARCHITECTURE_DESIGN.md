# 🏗 架构设计、抽象建模与项目深度梳理

本篇专注于提升你的“架构视野”，教你如何像专家一样思考和沟通。

---

## 🎨 专题一：设计模式的“设计哲学”

### Q1: 为什么我们要用设计模式？
*   **核心痛点**：软件的复杂性来源于**耦合**。
*   **一句话总结**：设计模式是对“封装、继承、多态”的极致应用，其目的是**封装变化**，通过多层的抽象将复杂逻辑拆解为可独立维护的单元。

### Q2: 挑一两个你理解最深的模式讲透？

#### 1. 观察者模式 (Observer) —— 响应式的基石
*   **应用**：LiveData, RxJava, EventBus。
*   **精髓**：定义了一对多的依赖关系。当状态变化时，自动通知所有注册者。
*   **高级感**：一定要提到 **“解耦了生产者和消费者”**。生产者不需要知道谁在看它，只需管好自己的数据。

#### 2. 策略模式 (Strategy) —— 告别 if-else
*   **场景**：App 有多种登录方式（微信、手机、游客）。
*   **实现**：定义一个 `LoginStrategy` 接口，不同方式各写一个类。
*   **价值**：符合**开闭原则**。未来增加“抖音登录”时，只需写个新类，不需要改动原来的判断逻辑。

## 🏗 专题二：抽象建模与工程化（SOLID 实战）

### Q1: 什么是“良好的接口设计”？
*   **契约精神**：接口要稳定，不应包含具体的实现细节。
*   **接口隔离 (ISP)**：不要设计一个“万能接口”。如果一个接口里有 20 个方法，用户只需其中 1 个，那就是设计失败。

### Q2: Android 现代架构分层 (Clean Architecture)
*   **View 层**：只管展示，不含逻辑。
*   **ViewModel 层**：持有 UI 状态，不持有 View 引用。
*   **Domain 层 (Use Case)**：处理纯纯的业务逻辑（可跨平台复用）。
*   **Data 层 (Repository)**：屏蔽数据来源（本地数据库 vs 云端 API）。

## 🚀 专题三：项目深度梳理（面试通关模板）

当面试官让你介绍项目时，请按照以下维度准备：

### 1. 业务划分与组件化
*   **如何解耦**：按照业务线（如：用户模块、订单模块、消息模块）进行 **组件化**。
*   **通讯机制**：模块间不直接引用，通过路由框架（ARouter）或 ServiceLoader 进行通信。

### 2. 技术选型理由 (Rationale)
*   **数据库**：为什么选 Room？（答：编译时检查、与 LiveData 原生集成）。
*   **网络**：为什么用 OKHttp + Retrofit？（答：类型安全、强大的 Interceptor 拦截器扩展）。

### 3. 性能优化闪光点（必须准备一个案例）
*   **案例**：我曾针对首页 List 进行了 **“大图加载优化”**。
*   **动作**：Hook 了 Glide 的缓存，并在 Native 层监控内存抖动。
*   **结果**：内存峰值降低 30%，首页 FCP（首次内容渲染）时间缩短 200ms。
