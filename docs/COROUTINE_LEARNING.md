# 🚀 Kotlin 协程面试核心指南

本文档专为应对大厂 Android/Kotlin 面试整理，抛弃繁文缛节，直击核心原理。

---

## ⚔️ 战役一：底层原理解析 (CPS 与状态机)

### Q1: 协程和线程到底有什么区别？为什么说它是“轻量级”的？
*   **线程**：OS 资源，切换开销大（内核态），占用内存多（约 1MB）。
*   **协程**：用户态逻辑，本质是代码块封装。切换由编译器生成的代码控制，占用内存极小（几十字节）。
*   **结论**：你可以启动 10 万个协程，但不能启动 10 万个线程。

### Q2: `suspend` 关键字到底做了什么？
*   **CPS 变换**：编译器修改函数签名，添加 `Continuation` 参数，用于记录后续逻辑。
*   **状态机**：编译器将函数体转为 `switch-case` 结构，通过 `label` 记录挂起点，实现暂停和恢复。

### Q3: 挂起 (Suspend) 和 阻塞 (Blocking) 的区别？
*   **阻塞**：卡死线程，无法干别的事。
*   **挂起**：暂停逻辑，**释放线程**。线程可以去执行其他协程，等挂起结束再切回来。

### Q4: 为什么必须要在 `CoroutineScope` 里启动？
*   为了 **结构化并发**。Scope 管理 Job，确保生命周期绑定，父取消则子必取消，防止内存泄漏。

## ⚔️ 战役二：结构化并发与取消

### Q1: `Job` 和 `SupervisorJob` 的区别？（高频）
*   **Job**：默认模式。一个子协程失败，会触发级联取消，**所有兄弟协程和父协程都会被取消**。
*   **SupervisorJob**：监督模式。一个子协程失败，**不会影响兄弟协程**。常用于 ViewModel。

### Q2: 协程的取消是实时的吗？为什么调用 `cancel` 没反应？
*   **核心**：协程的取消是 **协作式** 的，不是强制杀掉。
*   **原因**：如果协程内部正在执行紧密的计算循环（如 `while(true)`）且没有检查取消状态，它就不会停止。
*   **解决**：
    1. 使用 `isActive` 检查状态。
    2. 调用 `ensureActive()` 或 `yield()`。
    3. 调用 `delay()` 等挂起函数（它们内部会自动检查取消状态）。

### Q3: `cancel()` 和 `cancelAndJoin()` 的区别？
*   `cancel()`：发出取消信号，但不等待协程真正停止。
*   `cancelAndJoin()`：发出取消信号，并挂起当前协程，直到目标协程完全清理完毕。

## ⚔️ 战役三：异常处理机制

### Q1: 协程异常处理的“三条铁律”？
1.  **launch** 异常会向上抛出（除非有 ExceptionHandler），可能导致进程崩溃。
2.  **async** 异常会封装在 `Deferred` 中，在调用 `await()` 时才抛出。
3.  **根协程**（顶级协程）才适合放 `CoroutineExceptionHandler`。

### Q2: `coroutineScope` 和 `supervisorScope` 的区别？
*   **coroutineScope**：内部一个子协程崩了，整个作用域全部结束并抛出异常。
*   **supervisorScope**：内部一个子协程崩了，其他子协程不受影响。

### Q3: 为什么 `try-catch` 有时包不住协程异常？
*   如果你在协程外部 `try-catch { launch { ... } }`，这是包不住的。因为 `launch` 立即返回，异常是在另一个线程/协程里发生的。必须在协程内部的 `block` 里进行 `try-catch`。

## ⚔️ 战役四：Flow 响应式数据流

### Q1: 冷流 (Cold Flow) 和 热流 (Hot Flow) 的区别？
*   **冷流 (Flow)**：不订阅不生产。每次 `collect` 都会触发一遍生产者逻辑。
*   **热流 (StateFlow/SharedFlow)**：不管有没有订阅者，它都在那里运行。订阅者只能收到订阅后的数据（StateFlow 能收到最后一个值）。

### Q2: `StateFlow` vs `LiveData`？
*   **LiveData**：生命周期感知，只能在主线程更新，不支持操作符变换。
*   **StateFlow**：必须有初始值，支持丰富的 Flow 操作符（filter, map 等），跨平台（KMP 也能用），但不直接感知 UI 生命周期（需配合 `repeatOnLifecycle` 使用）。

### Q3: `SharedFlow` 的应用场景？
*   用于处理 **“一次性事件”**，如弹出 Toast、导航跳转、Snackbar 提示。它支持配置缓存大小和粘性策略。
