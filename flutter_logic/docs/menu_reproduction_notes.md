### 引导 1：先分析页面有什么内容（理解 UI 结构，不急写代码）

菜单页面（3467:32483 "呼出菜单"）是同一手柄页的一个状态，按 Figma 实际节点顺序分 5 层：

1. **底层手柄页**：背景 + 完整手柄（DPad/ABXY/select-start/L/R）
2. **底部辅助按钮**：SET 左 / 展开右，随手柄一起被蒙层暗化
3. **蒙层**：全屏 rgba(18,26,41,0.8)，暗化手柄聚焦菜单
4. **菜单面板**（342×322，位置 24,75）：6 项 3×2
   - 快速存档(覆盖快速存档) / 退出游戏
   - 存档管理(3/3已用) / 倍速
   - 快速读档(14:32) / 继续游戏(返回游戏，高亮焦点：紫底 #C9B9F9 + 紫框 #9272F2)
5. **中央 logo**：位置 174,778，菜单触发器，独立置于蒙层之上

**skill 修订**：已增加“先识别页面结构、z 层和交互状态，再提取元素数据”。

### 引导 2：菜单不是独立页面，是手柄页的「菜单显示态」

- 菜单显示时，底部**中间 logo 按钮高亮**（区别于正常态，正常态 logo 是 #e7edf8 @40% 弱化）
- 即：同一个手柄页，menuOpen 状态切换底部 logo 按钮高亮 + 蒙层/面板显隐
- 不是新页面，是状态的视觉变化

**skill 修订**：已增加页面状态机和跨状态差异检查。

### 引导 3：菜单卡片的特点

菜单 6 个卡片本质 =「图标 + 双行文字的圆角卡片」：
- 形状：rounded 8，167×102（普通）
- 背景：普通 #e7edf8（浅蓝灰）/ 焦点 #c9b9f9（浅紫）
- 内容：icon（34×34 padding5 内 24×24）+ title（Heavy 14）+ caption（Regular 12，部分无）
- 布局：水平 Row，icon 与双行文字整体垂直居中，gap 4
- 状态：普通（灰蓝底深字）/ 焦点（紫底紫字 + 凸出 wrapper + ring）

### 引导 4：只需一个公共 widget + 数据配置（三分离的真正含义）

- 卡片是**公共 widget**（MenuCard），6 个卡片 = 同一 widget + 不同 MenuItem 配置
- 继续游戏的高亮/凸出/ring 也是**配置驱动**（highlight: true 触发焦点态），不是硬编码分支
- 我之前的错：MenuItem 有数据，但 _item 是 MenuOverlay 私有方法 + 继续 wrapper 硬编码在 _panel 行3 —— 没真正"一个公共 widget + 配置驱动所有差异"

**skill 修订**：已增加“公共 widget + 数据配置全部显示、行为和初始状态”。

### 引导 5：焦点框抽公共 widget（FocusRing），统一控制

- 焦点框（hover ring：border #9272f2 + 白色渐变高光）是项目通用样式，正常项目会有统一组件
- UI 还原探索阶段，自己实现一个**独立公共 FocusRing widget**
- 所有卡片通过 `focused: true/false` 配置驱动焦点态（ring 显隐），统一控制有焦点/无焦点
- 之前错：继续游戏的 ring 硬编码在 _continueWrapper，不通用

**skill 修订**：已增加焦点/选中/hover 公共状态组件检查。

### 引导 6：整体结构想清楚后，grid 列表布局

- 整体结构分析完（页面层/状态/卡片/焦点），想清楚怎么实现，再开始
- 6 卡片是**列表布局**，间距通过 **grid** 实现（统一 gap 8，Figma）
- 获取 Figma 位置，从上到下依次（数据驱动顺序）
- 当前实现：`GridView.builder` + `SliverGridDelegateWithFixedCrossAxisCount`，普通单元固定高 102，横纵 gap 8

**skill 修订**：已增加“重复元素优先真实列表/Grid，由集合决定数量和顺序”。

### 引导 7：UI 跟数据走（核心实现决策）

- 之前的根本问题：**UI 没跟着数据走** —— 布局硬编码顺序，产品改菜单顺序/数量要改 UI 代码
- 正确：grid 遍历 List<MenuItem>，顺序/数量全由数据决定，UI（grid 容器）不动
- 这是**实现决策**（架构选择），不是细节：数据驱动 UI，而非 UI 定死数据

**skill 修订**：已把“UI 跟数据走”提升为顶层原则。
